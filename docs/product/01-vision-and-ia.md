# 01 · 产品愿景 · 定位 · 信息架构

> 本文确立 PromptForge 的产品定位、目标用户、竞争坐标与差异化壁垒，并给出**融合双入口**的信息架构与导航模型——这是所有 deep-dive 文档的心智锚点。

---

## 1. 一句话定位

**PromptForge / 词炉**：面向个人创作者的跨平台（macOS + Windows）**生图提示词管理与生产桌面 App**——把「提示词库管理 + 模板组合造词 + 用户自带 Key 直调云 API 生图 + 结果与成本账本」打包成原生桌面体验，一次性买断。

**Slogan**：锻造你的生图提示词 / Forge your image prompts。

---

## 2. 目标用户画像

| 画像 | 描述 | 核心痛点 | PromptForge 的解 |
|------|------|----------|-------------------|
| **P1 · 高频生图创作者**（主） | 每天用 gpt-image / SD / MJ / Flux 出图的独立设计师、内容创作者、AI 绘画爱好者 | 提示词散落各处难找、复用靠手抄改字、切模型要改语法、无桌面管理工具 | 库+组合+多 target 序列化+一体化生图 |
| **P2 · 提示词工程玩家** | 钻研 prompt 结构、维护自己的「配方库」、追求可复现 | 缺可版本化、可组合、可对比的工作台 | 三层组合引擎 + 版本管理 + 排列组合 |
| **P3 · 中转站 API 用户** | 已购中转站/官方 Key，原来靠脚本或网页调用 | 无 UI、无管理、无历史成本 | Provider 配置 + 直调 + 历史成本看板 |
| **P4 · 轻度试验者** | 偶尔想「输入一句话看看出什么图」 | 重工具门槛高 | **Chat 快速试验入口**（低门槛） |

**设计取舍**：主路径为 P1/P2/P3 服务（生产力），Chat 为 P4 及 P1 的「灵感速记」服务（轻量）。二者不是二选一，而是**同一资产池的两种进入方式**。

## 3. 竞争坐标与市场空白

> 详见原始调研 `生图提示词管理App_调研与设计建议.md` §一。此处提炼产品决策相关结论。

| 能力维度 | 提示词管理类<br>(PromptBox/PromptStorm/AIPRM) | 生图客户端<br>(Draw Things/ComfyUI/Fooocus) | 云生图<br>(MJ/Krea/Recraft) | **PromptForge** |
|----------|:---:|:---:|:---:|:---:|
| 原生桌面 Mac+Windows | ❌ 全 Web/扩展 | 🟡 部分单平台 | ❌ 全 Web | ✅ **双平台原生** |
| 提示词库管理 | ✅ | ❌ 原始 | ❌ | ✅ |
| 模板/变量/组合 | 🟡 仅基础变量 | ❌ | ❌ | ✅ **完整三层引擎** |
| 多模型 target 语法感知 | ❌ | ❌ | ❌ | ✅ **独家** |
| 自带 Key 直调云 API | ❌ | ❌ 本地推理 | ❌ 无桌面 | ✅ |
| 生图+管理一体 | ❌ | ❌ | ❌ | ✅ |
| 定价 | 订阅 | 免费(本地) | 订阅 | ✅ **一次性买断** |

**结论**：**「原生桌面 + 完整组合引擎 + 多 target 序列化 + 自带 Key 直调 + 一体化 + 买断」的组合是真实市场空白。** 没有任何单一竞品覆盖这个交集。

## 4. 差异化壁垒（护城河，按强度排序）

1. **多模型 target 感知序列化** 🥇 — 同一份 Composition，切 Provider 自动输出 `(word:1.5)` / `word::15` / `very word` / 自然语言。竞品全无。→ [15-differentiators](15-differentiators-deep-dive.md) §多-target
2. **AST 中间表示 + 点击反查** 🥈 — 渲染保留每段来源 slot，点预览词高亮来源。引擎已具备 segments，UI 未做。→ [15](15-differentiators-deep-dive.md) §AST 反查
3. **完整三层组合引擎** 🥉 — Fragment/Template/Composition + 6 种插值语法 + 权重 + 负面 target 适配。引擎单测已 21/21 通过。→ [11-composer](11-composer-deep-dive.md)
4. **原生桌面观感** — vibrancy/Mica、原生标题栏、系统字体，非 Electron「网页套壳」感。
5. **无后端 P2P 分享** — 分享卡片 PNG + deeplink 导入，与买断定价契合，无需服务器。→ [15](15-differentiators-deep-dive.md) §分享卡片
6. **本地优先 + 隐私** — 数据全本地 SQLite，密钥 safeStorage OS 级加密，不内置任何中转站域名，规避合规风险。

## 5. 信息架构：融合双入口

### 5.1 核心心智

```
                        ┌─────────────────────────────────────┐
                        │           统一资产池（本地）          │
                        │   Prompts · Fragments · Templates    │
                        │   Compositions · History · Providers │
                        └─────────────────────────────────────┘
                            ▲                         ▲
              「提升 / promote」               「消费 / consume」
                            │                         │
        ┌───────────────────┴──────┐      ┌───────────┴────────────────────┐
        │      轻入口：Chat         │      │   核心主路径（生产力）           │
        │  快速试验 · 即输即生       │      │  Library→Composer→Generate→     │
        │  多图对比 · 灵感速记       │      │  History                        │
        └──────────────────────────┘      └─────────────────────────────────┘
```

**两条入口共享同一资产池**，通过「提升」动作单向流转，不重复造轮子：

| 流转 | 触发 | 结果 |
|------|------|------|
| Chat → Library | Chat 消息「存为提示词」 | 该 prompt 文本入库，`source=manual`，可后续管理 |
| Chat → Composer | Chat 消息「拆解到画布」🆕 | 把这句话作为初始 body 进 Composer 深化 |
| Composer → Library | 右栏「另存为 Prompt」 | Composition 产物入库，`source=composition` |
| Library → Generate | 卡片/详情「生成图像」 | 用库中 prompt 直接生图 |
| Library → Composer | 卡片「在画布打开」🆕 | 以该 prompt 为 body 二次组合 |
| History → 任意 | 详情「回填 Composer / 另存 Prompt / 再次生成」 | 结果反哺资产 |

### 5.2 定位边界（避免 Chat 吞掉主路径）

| | Chat 轻入口 | Library/Composer 主路径 |
|---|---|---|
| **心智** | 「我想试试这句话出什么图」 | 「我在经营我的提示词资产/批量生产」 |
| **产物** | 临时消息流，默认不入库 | 一等公民资产，长期沉淀 |
| **门槛** | 零配置即可用（配好 Provider 后） | 需要理解库/组合概念 |
| **不做** | 不做复杂组合、不做批量管理 | —— |
| **反模式** | ❌ 把 Chat 做成唯一功能、Library 荒废 | ❌ 强迫轻度用户先学组合 |

> **产品红线**：Chat 是「入口」不是「归宿」。任何在 Chat 里产生的有价值资产，都应有一键「提升」进主路径的通道；反之主路径的资产可「投喂」回 Chat 快速迭代。**绝不让 App 沦为「又一个聊天生图客户端」。**

### 5.3 关于 Studio

当前代码存在 `features/studio`（悟空创作台生图，见 [12-generation](12-generation-deep-dive.md)）。产品决策：**Studio 归并为 Generate 主路径下的一个「Provider 能力面」**，不作为独立顶层导航。若悟空 API 有独家能力（如特定模型/参数），以「高级生成参数」形式并入 Generate；否则逐步收敛。详见 [12](12-generation-deep-dive.md) §Provider 生态。

## 6. 导航模型与全局布局

### 6.1 顶层导航（左侧 Sidebar 主导航）

```
┌──────────────┐
│  [TitleBar]  │  ← 原生拖拽区 + 窗口按钮
├────┬─────────┤
│ 📚 Library   │  ← 落地页（默认）
│ 🧩 Composer  │
│ ⚡ Generate   │  ← 生图工作区（含快速 Chat tab）
│ 🕘 History    │
│ ─────────    │
│ ⚙️ Settings   │  ← 底部固定
└────┴─────────┘
```

**决策**：
- **落地页 = Library**（沿用 docs/00 决策 #1，最高频动作是找/改/生成）。
- **Generate 作为独立生图工作区**，内含两个 tab：**「快速」(Chat 式) / 「精修」(来自 Library/Composer 的参数化生成)**。这就是「融合双入口」在导航上的落点——Chat 不再是割裂的顶层，而是 Generate 的快速模式。
- **Composer** 独立顶层（三栏已满，需要完整空间）。
- **History** 独立顶层（结果账本）。
- **Settings** 底部固定。

> 迁移说明：现状代码里 Chat 是独立主入口、Studio 是独立入口。目标态是 **Chat + Studio → 收敛进 Generate 工作区的模式切换**。这是 [14-chat](14-chat-deep-dive.md) 与 [12-generation](12-generation-deep-dive.md) 的联合改造点，列为 P1。

### 6.2 全局三栏骨架（沿用 docs/06 §6）

```
┌────────────────────────────────────────────────────────┐
│  TitleBar (拖拽区, h-10)                                 │
├──────────┬──────────────────────────┬──────────────────┤
│  Sidebar │     主区（路由切换）      │  右侧检视（可选） │
│  (240px) │  Library/Composer/...    │  (320px, 可折叠)  │
└──────────┴──────────────────────────┴──────────────────┘
```

- **右侧检视栏**：Library 显示选中 Prompt 详情；History 显示选中记录详情；Composer 页隐藏（三栏已满）。
- **命令面板**（`Cmd/Ctrl+K`）：全局跳转 + 动作，已有骨架，纳入 [17-uiux](17-uiux-patterns.md)。

### 6.3 全局快捷键（统一定义，各 deep-dive 引用）

| 快捷键 | 动作 | 作用域 |
|--------|------|--------|
| `Cmd/Ctrl+K` | 命令面板 | 全局 |
| `Cmd/Ctrl+N` | 新建（上下文相关：Library=新提示词） | 主区 |
| `Cmd/Ctrl+F` | 聚焦搜索 | Library/Composer 库 |
| `Cmd/Ctrl+Enter` | 生成图像 | Generate/Composer |
| `Cmd/Ctrl+S` | 保存当前编辑/另存为 Prompt | Editor/Composer |
| `Esc` | 关闭对话框/取消生图 | 全局 |
| `1..5` | 快速切换顶层导航 | 全局（非输入态） |

## 7. 产品原则（不可妥协）

1. **本地优先**：数据全本地，无强制登录，无云依赖（分享用 P2P deeplink）。
2. **Provider 无关**：不内置任何中转站域名，用户自配后端。
3. **密钥安全**：明文永不入 DB、永不过 IPC 返回、永不进日志（`docs/01` §3 安全红线）。
4. **资产单向提升**：Composition→Prompt 单向，库不被半成品污染（`docs/00` 决策 #2）。
5. **原生克制**：中性灰阶 + 单一强调色 + 系统材质，信息密度高，不炫技。
6. **可验收**：每个功能有客观验收标准，不靠「感觉完成」。

---

## 8. 成功指标（产品北极星，供设计取舍参考）

| 层级 | 指标 | 目标 |
|------|------|------|
| **激活** | 新用户从安装到首次成功生图的时长 | < 10 分钟 |
| **核心价值** | 用户是否沉淀 ≥ 5 条提示词资产 | 首周达成率 |
| **差异化** | 使用 Composer 产出并另存的比例 | 体现「不是聊天客户端」 |
| **留存** | 用户回访是否复用历史/库 | 资产复用率 |

> 无遥测后端时，这些指标作为**设计决策的定性指南**（每个功能自问：它帮用户更快激活/更多沉淀/更强差异化吗？），不作强制埋点要求。
