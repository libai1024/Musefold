# 17 · UI/UX 模式与设计系统扩展 —— Deep Dive

> **本文定位**：贯穿全局的**跨切面交互模式库 + 状态矩阵 + 可执行 a11y/动效/跨平台规格**。
> 它 **扩展** `docs/06-ui-design-system.md`（基础 token/配色/窗口/组件规格）——**不重写**；docs/06 定义「长什么样」，本文定义「怎么动、什么状态、键盘怎么走、缺哪些模式」。
> 结构与 [10-library-deep-dive.md](10-library-deep-dive.md) 一致（现状→模式→任务卡），但因是横切文档，主体是「模式库 + 矩阵」而非单一功能拆解。
> 引用：`docs/06`（基础）、[01-vision-and-ia.md](01-vision-and-ia.md) §6（导航/快捷键）、§7（原生克制）。图例见 [README §6](README.md)。

> **创作台新增模式（2026-08-04）**：比例选择使用 `RatioPicker` 自绘弹层；触发器和选项都显示长宽轮廓、比例数字和用途标签。工作台与设置页禁止使用系统原生 `<select>`，菜单支持选中态、点击外部关闭和 Esc 关闭。
> **比例选择补强（2026-08-05）**：`RatioPicker` 弹层升级为卡片式预览网格，参考旧版创作台的「矩形轮廓 + 比例数字 + 用途标签」表达；设置页默认比例行新增常驻预览网格，可不展开菜单直接点击切换，并保持与 Workbench 默认参数同步。
> **比例摘要预览（2026-08-05）**：工作台比例弹层顶部新增当前画幅摘要预览，设置页默认比例行同步展示同源摘要卡；摘要与卡片选择共用 `resolveRatioOption`，切换后矩形方向、比例数字、用途标签和像素档位同时更新。
> **比例选项扩展（2026-08-06）**：保留 OpenAI 兼容接口合法像素档位的同时，补齐旧版创作台/Wukong 文档常用画幅 `3:4`、`4:3`、`4:5`、`5:4`、`21:9`；比例预览回到旧版「白底矩形轮廓 + 比例数字 + 用途标签」表达，OpenAI 侧映射到最接近的横/竖像素档，异步创作台侧继续传精确比例串。
> **比例下拉 UI 收口（2026-08-06）**：工作台与 Composer 的 `RatioPicker` 触发器升级为应用内自绘按钮，展示白底画幅轮廓、比例和像素档；展开层为玻璃浮层 + 卡片式预览网格。设置页不再重复放置下拉、画幅摘要卡和常驻网格，而是保留一行文字摘要与一套可直接点击的预览网格，明确禁止回退到系统原生 `<select>`。
> **比例下拉可访问性与窄屏收口（2026-08-06）**：比例卡片支持方向键、Home/End、Enter/Space 选择、Esc 关闭；弹层打开后聚焦当前选项，关闭后焦点同步回到触发按钮。窄屏弹层改为右对齐并限制在视口内，内部网格独立滚动，避免被创作台主区裁切；Workbench 与 Settings 继续共用同一预览语义。
> **生成 Composer 层级收口（2026-08-06）**：底部输入区遵循“输入优先、参数按需展开”：服务商/模型为低对比度上下文控件，比例为紧凑画幅入口，质量/数量/反向提示词进入统一“生成设置”浮层，发送/停止使用圆形图标按钮；无 Provider 时不渲染死的禁用生成按钮。
> **比例卡片视觉清晰化（2026-08-06）**：比例卡片统一为单层轻卡片 + 独立画幅舞台 + 比例/用途/像素三行信息；画幅舞台留足横竖比例的完整高度，不叠加装饰基线，不允许白色比例框被舞台裁切。Workbench 弹层与 Settings 常驻网格共享同一组件，Settings 当前值只保留紧凑文字摘要，避免同一比例连续出现三次。
> **生成完成态操作收口（2026-08-06）**：`继续探索 / 采用此方向制作 / 查看生成历史` 等回合动作必须使用统一圆角操作按钮；图片悬浮工具与更多菜单分别使用稳定的图标按钮和菜单行样式，禁止未定义 class 退化为浏览器裸按钮。
> **命令面板定位收口（2026-08-06）**：命令面板横向居中只由独立 `translate` 属性负责，入场动画只做纵向位移和缩放；桌面严格对齐视口中心，窄屏使用 `calc(100vw - 32px)` 保留左右 16px 安全边距，并限制最大可用高度。
> **工作台推荐词与历史入口（2026-08-06）**：空态推荐词使用本地组合式词库，每次进入空态或点击「换一组」更新候选；点击候选只回填并聚焦底部输入框，不自动生成。历史详情主动作使用「再次制作」，跳转制作模式并回填提示词/参数，用户手动确认后提交；失败态的“重试”仍是独立的同参恢复动作。
> **工作台上下文槽位（2026-08-06）**：Provider、Model、Ratio、More Settings 四个底部上下文控件使用固定宽度槽位，选项文本变化只能截断，不能改变整体输入栏布局；提交后保留规范化提示词，Composer 在生成中和完成后继续可编辑。
> **Toast 系统通知（2026-08-06）**：Toast 使用实色弹层、细边框、状态小图标和文本操作，不使用左侧彩色强调线、渐变或玻璃装饰；入场只做短距离淡入，关闭按钮支持键盘，悬停/聚焦时暂停自动关闭。

## 1. 目的与范围

各 deep-dive（10–16）的任务卡反复出现同一批词：**「空态」「骨架屏」「toast 反馈」「5s 撤销」「拖拽高亮」「脏检查」「乐观更新回滚」**。这些是**跨功能复用的交互契约**，若每张卡各写各的会漂移不一致。本文把它们收敛为**单一事实源**，各 deep-dive 引用本文的模式编号即可。

**本文负责**：

| 范围 | 内容 | 章节 |
|------|------|------|
| 交互模式库 | 空/加载/错误/成功/确认撤销/拖拽/右键/脏检查/乐观更新 的统一规范 | §3 |
| 命令面板 | `⌘K` 命令注册模型、导航+动作、检索、最近项 | §4 |
| 快捷键系统 | 扩展 01 §6.3 为完整规格：作用域/冲突/输入态禁用/可发现性 | §5 |
| 动效系统 | `motion.css` token、时长缓动、reduced-motion 全局开关、进出场 | §6 |
| 可访问性 | 可执行 checklist（focus ring/键盘/ARIA/对比度/reduced-motion） | §7 |
| 跨平台原生 | mac vibrancy vs win Mica、拖拽区、`usePlatform` 条件样式、字体栈 | §8 |
| 组件状态矩阵 | Button/Input/Card/列表项/Tab 的 7 态明细 | §9 |
| 深色模式与主题 | 三态主题源、跟随系统、毛玻璃半透明处理 | §10 |

**本文不负责**（归属他处，避免重复）：基础配色/圆角/字号 token（docs/06 §3/§4）、单个功能的业务交互（各 deep-dive §4）、IPC 契约（docs/07）。

**读法**：Opus 开发任意功能卡时，凡涉及上表模式，**先来本文对齐模式编号，再回功能卡实现**。§11 任务卡只收「横切基础设施缺口」，功能内交互仍在各自 deep-dive。

### 2.1 UI 基元（`src/components/ui/`）—— 覆盖良好

### 2.2 提示词资料条目与检视栏

Library 的默认呈现是高密度列表，使用实色表面、细边框和清晰间距。禁止在提示词卡片上使用玻璃背景、`backdrop-blur`、渐变、强阴影或选中态左侧强调条。选中态只通过浅色背景和 accent 边框表达；悬停/键盘聚焦才出现复制、查看作品和更多操作。

列表舒适密度约 104px 高、6px 间距，紧凑密度约 88px 高、4px 间距。正文为自然文本两行预览，描述放入右侧详情，元信息保持单行可读。网格是可选视图，图片优先，无图用平面文本占位，不加底部渐变遮罩。

右侧检视栏约 320px，顶部使用 `[详情] [作品 N]` 分栏。点击卡片默认详情；点击卡片的 Images/查看作品操作时，同时选中条目、展开检视栏并进入作品。作品默认只展示成功图片，支持切换失败/取消记录；图片失效必须保留尺寸并显示错误态，不能让布局坍塌。

### 2.3 制作模式引用侧栏

只有 Generate Workbench 的制作模式显示引用栏。桌面端默认展开、约 300px 宽，可折叠；窗口宽度不超过 1100px 时改为右侧覆盖抽屉，并保留遮罩和 Esc/关闭按钮。探索模式隐藏该栏，但不清空制作草稿中已有引用。

引用栏使用独立搜索状态，150ms 防抖调用 `prompt.list({ search })`，不改变 Library 的搜索/标签/文件夹筛选。结果项可展开正文；用户可引用整条提示词，也可直接选中文本后引用选段。每条引用显示标题与「整条/选段」来源，输入区上方以实色来源条展示，可单独移除，不使用富文本编辑器。

### 2.4 状态与可访问性契约

- 引用栏覆盖搜索加载、空结果、加载错误、正文展开、重复引用、超过 4000 字、达到 6 条和窄屏抽屉状态。
- 引用不会触发生图；用户正文为空但有引用时允许提交。最终 Prompt 超过 8000 字时禁用提交并明确提示移除/缩短，不自动截断。
- 键盘焦点必须可见；侧栏、作品分栏、图片 Lightbox、引用条移除和关闭动作均可用 Tab/Enter/Esc 操作。

### 2.4 作品关联反馈

提示词详情中的「作品」分栏必须把“有记录”和“能读到记录”区分开：加载中显示统计状态，IPC 版本不兼容显示可操作的升级提示，查询失败显示重试，而不是直接渲染 0。作品缩略图和失败/取消状态行都应显示来源原因，帮助用户判断记录是直接制作、引用整条、引用选段还是由作品保存产生。关联关系必须来自稳定 ID/关系表；界面不得因为正文相同就暗示两条记录已经关联。

网格视图承担照片册浏览，不是列表卡片的放大版。桌面内容区固定两列，低于 520px 才降为一列；关联作品按 1/2/3/4 张自适应拼贴，整块相册保持稳定高度，动态图片和计数不能撑开卡片。每张图都可点击/键盘聚焦并直接打开 Lightbox，数量入口打开完整作品检视；没有关联作品时明确区分提示词封面和正文回退，不能把封面标成生成作品。
- 颜色只表达层级和状态，通知使用实色 Toast；不使用大面积渐变、发光、玻璃高光制造“AI 装饰感”。
