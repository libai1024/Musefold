# ZCode UI 布局学习方案

版本：2026-08

## 1. 文档目的

这是一份面向 UI 学习、产品拆解和复刻实现的 ZCode 当前界面研究方案。它不只描述“页面上有什么”，还记录以下关系：

- 哪些区域属于固定外壳，哪些区域属于当前任务内容。
- 哪些按钮直接执行动作，哪些按钮只是打开选择器或二级面板。
- MainView、左侧工作区栏、右侧面板和弹层如何叠加。
- 同一个组件在默认、悬停、打开、禁用、运行中和空状态下如何变化。
- 在 Musefold 中哪些模式可以借鉴，哪些是 ZCode 面向编码 Agent 的专属结构。

本方案以 2026-08-25 运行中的 ZCode 桌面应用为观察对象。窗口约为 1208 x 766 px，观察重点为暗色工作区、中文界面、Musefold 项目和 `main` 分支。

## 3. 一句话总览

ZCode 是一个“固定左侧工作区导航 + 中央任务工作台 + 可独立收起的右侧上下文面板”的三栏桌面应用。中央区域是主要工作面，左右区域都服务于任务切换和上下文管理；菜单、搜索和引导使用浮层或模态覆盖，不改变主布局的基本分栏关系。

## 4. 术语与布局坐标

| 术语 | 本方案中的含义 |
| --- | --- |
| Shell | 应用最外层窗口、标题区、左侧栏、中央内容和右侧栏共同形成的稳定外壳 |
| Workspace sidebar | 左侧固定工作区栏，负责工作区、项目、分组、任务和全局入口 |
| MainView | 中央任务主视图，包含任务头、消息流和底部 Composer |
| Right panel / rail | MainView 右侧的上下文面板，包含文件、终端、变更、浏览器等标签 |
| Dock | 参与主布局计算的固定区域；打开后会压缩 MainView 宽度 |
| Overlay | 浮在内容之上的菜单、搜索、引导或对话框；通常带遮罩或局部定位 |
| Composer | 面向 Agent 的输入和控制区，固定在 MainView 底部 |
| Popover | 锚定在触发按钮附近的小型选择菜单，不改变主布局 |

推荐把 1208 px 宽窗口抽象为：

```text
window
├── title / traffic-light safe area
└── app shell
    ├── workspace sidebar       约 255 px
    ├── vertical splitter       1 px 左右
    ├── MainView                flex: 1
    │   ├── task header
    │   ├── message stream
    │   └── Composer
    ├── right panel             约 230-265 px，可收起
    └── overlay layer           只在需要时出现
```

实际宽度应使用可拖拽约束而非硬编码；上述数值仅用于理解比例和截屏复盘。

## 5. 关键设计结论

### 5.1 左侧栏是工作区导航，不是普通菜单

它同时承载工作区切换、项目树、任务列表、搜索、自动化、插件市场、连接使用和设置。项目与任务在左侧栏中形成可扫描的层级，而不是把所有内容丢给路由页面。

### 5.2 MainView 是连续工作面

任务标题、对话、工具调用、文件变更和输入框共同组成一条纵向工作流。消息流允许较长滚动，Composer 保持底部可用，任务的控制信息放在顶部而不是分散到卡片角落。

### 5.3 右侧面板是 dock，不是遮罩抽屉

打开右侧面板时，MainView 变窄，Composer 也随中心列变窄；关闭后中心列恢复。右侧面板没有覆盖中央内容，也没有遮罩层。右侧标签搜索是独立的局部 popover。

### 5.4 复杂操作分为三种表面

- Popover：项目、分支、模型、权限、界面主题等短列表选择。
- Command center：全局搜索和动作入口，居中、带遮罩、可键盘检索。
- Modal：首次启动引导、确认和需要用户完成的多步操作。

## 6. 采样边界

本方案覆盖当前可见和可访问的主要桌面界面：

- 工作区首页和新建任务。
- 已有任务 MainView。
- 任务消息、工具调用、文件变更、反馈和复制等消息操作。
- Composer 全部主要控制。
- 右侧面板、标签搜索和收起状态。
- 全局搜索/命令中心。
- 设置导航：常规、外观、模型设置、浏览器、记忆、子智能体、插件、MCP 服务器、技能、命令、钩子、索引库、使用统计、引导。
- 连接使用菜单、项目选择器、分支选择器以及常见上下文菜单。

说明：这是 UI 结构研究，不是源码级组件树的断言。精确 CSS token、内部实现名称和不可见的 hover 逻辑需要继续通过源码或自动化测试验证。

## 7. 使用这份方案学习一个页面

对任意页面按以下顺序记录：

1. 先画区域边界：固定栏、滚动区、底部固定区和浮层。
2. 再列控件：标题、说明、按钮、开关、输入框、标签、列表行。
3. 标记动作：执行、导航、打开 popover、切换状态、危险操作。
4. 记录状态：默认、hover、focus、disabled、loading、empty、selected、error。
5. 最后记录尺寸关系：左右 padding、行高、列宽、间距、圆角、边框和颜色层级。

## 8. 复刻验收最小集

- 窗口缩放后左侧栏不挤压到不可用，MainView 至少保留可读宽度。
- 右侧面板打开时中心内容变窄，关闭时恢复；二者没有重叠或遮挡。
- Composer 始终贴近 MainView 底部，长消息滚动不穿透到输入控制。
- 左侧项目、分组、任务层级在展开和收起时保持稳定的缩进。
- 所有图标按钮有可发现的名称，危险按钮有明确的红色或确认状态。
- 搜索、选择器和引导弹层打开时焦点进入浮层，关闭后焦点返回触发控件。
- 页面没有把状态开关伪装成文本按钮，也没有把选择器伪装成普通输入框。
