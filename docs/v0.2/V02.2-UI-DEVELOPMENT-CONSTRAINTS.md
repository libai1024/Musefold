# PromptForge v0.2.2 · UI 开发约束

> 状态：已执行并完成 v0.2.2 收口审计，2026-08-10
> 效力：v0.2.2 起，任何新增或修改渲染进程界面的提交都必须满足本文。与本文冲突的实现视为缺陷。
> 定位：设计文档说明"长什么样"，本文说明"不许怎么做"和"怎么验证"。
> 上游：[`DEVELOPMENT-RULES.md`](DEVELOPMENT-RULES.md) §4 仍然全部有效；本文是它在 UI 层的展开与可执行化。

---

## 0. 为什么需要这份文档

v0.2.1 之前的 UI 规则散落在六份文档里（开发规则 §4、交互规范 §2.3、体验设计 §2.6、UI 模式 §2.2、产品愿景 §6、设计系统文档）。它们互相不矛盾，但没有一条是可以被脚本检查的，所以每一条都被违反过：

- 规则说"避免玻璃叠加"，`globals.css` 是完整 Liquid Glass 体系。
- 规则说"图标不重复"，全项目 156 个图标、8 组语义重复。
- 规则说"不使用原生 `<select>`"——这条被遵守了，因为它具体、可搜索、可断言。

差别在于**可检查性**。本文只写可以被 grep、被单测、被 E2E 断言的约束。

## 1. 术语（唯一事实源）

界面上的中文字符串必须使用下表词汇。同义替换视为缺陷。

| 概念 | 界面用词 | 禁止 |
|---|---|---|
| 生成图片的工作区 | 制作工作台 | 创作台、生成器、Studio、画布 |
| 配方的管理与搭建入口 | 配方制作台 | 配方库、配方管理、模板库 |
| 长期可复用结构 | 配方 | 模板、预设、Recipe |
| 配方内不变内容 | 固定规则 | 固定块、静态块、固定片段 |
| 配方内每次修改的内容 | 每次变化 / 变量字段 | 槽位、slot、占位符、参数 |
| 带标题的可复用素材 | 复用片段 | 素材块、Fragment、片段库 |
| 只影响本次运行的输入 | 本次补充 | 临时提示、附加提示、补充说明 |
| 基于结果继续调整 | 继续微调 | 二次生成、迭代、refine |
| 提示词资产库 | 提示词库 | 素材库、Library、词库 |
| 生成记录 | 生成历史 | 历史记录、记录、History |
| 无 AI 的手动搭建 | 从空白结构搭建 | 手动创建、空白模板 |

依据：交互规范 `:100` 的内容块表、`:69` 的命名区分要求、开发规则对术语收敛的记录。

**内部概念不得出现在默认界面**：变量 key、AST、segment、Provider 参数映射、Prompt 哈希、`revisionId`、`blockId`、`materialRevisionId`。它们可以出现在开发者可见的调试位置或"高级"折叠区，不能出现在主流程（规范 `:107`）。

## 2. 材质约束

### 2.1 模糊只属于瞬时层

`backdrop-filter` / `-webkit-backdrop-filter` 允许出现的位置**穷举如下**：

- 命令面板
- 下拉菜单 / 弹层 / popover
- 模态对话框及其遮罩
- toast
- 覆盖式抽屉的遮罩

其他任何位置使用 `backdrop-filter` 视为缺陷。特别是：**内容区卡片、列表行、侧栏、标题栏、Composer、检视栏、面板不得使用**。

依据：开发规则 `:51`、交互规范 `:92`、UI 模式 §2.2。

### 2.2 表面必须实色

`--bg-window`、`--bg-sidebar`、`--bg-elevated` 必须是不透明色值。窗口级半透明由 Electron 的窗口属性负责，不由 CSS 模拟。

`--bg-hover`、`--bg-active`、`--bg-inset` 是叠加层，允许 alpha。

### 2.3 阴影只有两级

```
--shadow-sm    允许：hover 微抬
--shadow-pop   允许：仅 §2.1 列举的瞬时层
```

内容区卡片用 `--border-subtle` / `--border-default` 建立层级，**不用阴影**。禁止新增阴影变量。

### 2.4 禁止的装饰

以下在任何位置都不允许：

- 渐变背景（`linear-gradient` / `radial-gradient`）作为表面色。例外：`skeleton` 的 shimmer、比例预览的画幅示意。
- 发光（`box-shadow` 带彩色扩散、`filter: drop-shadow` 带 accent 色）。
- 卡片左侧 accent 强调条（UI 模式 §2.2 明文禁止）。
- 图片底部渐变遮罩。
- 装饰性 AI 图形、粒子、光晕、网格背景。
- 品牌色块拼贴。

### 2.5 圆角必须来自阶梯

只允许 `--radius-xs/sm/md/lg/xl/full` 与其 Tailwind 别名。禁止任意 `rounded-[13px]`。

选择依据是容器尺度，规则见设计文档 §2.3。

## 3. Accent 纪律

`--accent` / `--accent-hover` / `--accent-press` / `--accent-soft` / `--accent-ring` 与 Tailwind 的 `accent-*` 别名，只允许用于：

1. 当前选中项（导航项、列表选中行、分段控件当前项、Tab 当前项）
2. 焦点环
3. 主动作按钮的底色
4. 需要用户处理的状态（未配置、必填缺失、有冲突）
5. 品牌标记（标题栏 logo 底、助手头像）
6. 双向反查的高亮

**禁止**：卡片装饰、分区标题着色、图标批量着色、hover 时整行变 accent、进度条以外的填充。

一屏之内实心 accent 主动作**最多一个**。如果一个页面有两个都想用实心 accent 的按钮，说明其中一个应该是次动作。

## 4. 图标约束

### 4.1 单一导出口

所有图标必须从 `src/components/ui/icons.ts` 导入。组件中直接 `import { X } from 'lucide-react'` 视为缺陷。

```ts
// src/components/ui/icons.ts
export {
  Sparkles as IconGenerate,
  LibraryBig as IconLibrary,
  Layers as IconRecipe,
  RotateCcw as IconRetry,
  RefreshCw as IconReload,
  // ...
} from 'lucide-react';
```

单一导出口是"一个概念一个字形"唯一能被机械保证的方式。

### 4.2 语义唯一

设计文档 §4 的映射表是契约。新增图标前必须确认该语义未被占用；复用已有语义必须复用同一导出名。

高频冲突点，特别注意：

| 易错 | 正确 |
|---|---|
| 失败后再试用 `RefreshCw` | `IconRetry`（`RotateCcw`） |
| 重新拉列表用 `RotateCcw` | `IconReload`（`RefreshCw`） |
| 复制文本与复制对象用同一个 | `IconCopy` vs `IconDuplicate` |
| 设置与参数浮层用同一个 | `IconSettings`（`Settings2`）vs 生成设置浮层的 `SlidersHorizontal` |

### 4.3 规格

线宽 1.75（选中 2.25）；尺寸 14/16/20 三档；`round` 端点；颜色继承 `currentColor`，仅状态图标自带语义色。

## 5. 交互完整性

### 5.1 十二态

每个新交互必须明确实现并可验收：

```
默认 · hover · focus-visible · disabled · loading
empty · success · partial · failed · cancelled · retry · 窄屏
```

依据开发规则 `:53`。缺任一态视为未完成。

`partial`（部分成功）不可省略：多图生成允许部分成功，界面必须能同时显示成功与失败的单图。

### 5.2 动作必须真实

主要动作必须是可操作按钮。禁止：裸文本充当按钮、只改视觉不接功能的控件、渲染出来就禁用且无说明的按钮。

无 Provider 时不渲染死的禁用生成按钮，而是渲染引导配置的入口（现状已实现，保留）。

### 5.3 不允许的隐式行为

以下动作**绝不能触发图片生成请求**（规范 `:796`）：

- 点击配方目录条目
- 点击推荐方向 / 建议 chip / 微调建议 chip（只回填输入框）
- 保存配方 / 发布版本
- 「保存并开始制作」（只跳转到使用配方页）
- 「带入制作工作台」（只交接快照）
- 切换 Provider / 模型 / 比例 / 质量 / 数量
- 移除来源条锚定（配方对话降级为自由对话，正文保留）
- 关闭预览

只有用户明确点击发送按钮才创建生成任务。

### 5.3.1 工作台对话模型（v0.2.2）

- **无模式开关**：工作台是单一对话面，形态由来源条在不在决定，不得重新引入探索/制作切换。`generationMode` 字段下线。
- **对话首次发送才落库**：点「＋新创作」是草稿态，首个 run 落地才写库、才进侧栏对话列表。未发送离开不留空壳。
- **一条对话最多一个锚**：换配方或新建 = 开新对话（清空当前时间线，旧 run 在历史里不丢）。
- **气泡双形态**：自由回合显示用户输入文本；配方回合气泡只显示变量值+本次补充，完整渲染 prompt 进折叠，不把系统渲染的长文当作用户输入直显。
- **交接后 Composer 正文留空**，不预填渲染 prompt。
- **微调**用底部 Composer 微调态 + 上下文条，结果作为下一回合 + 回链；不在结果卡内嵌第二个 composer。分支树只在生成历史呈现，不在工作台画树。

依据历史工作台交互规格；当前工作台行为以源码、测试和对应版本文档为准。

### 5.4 时间尺度不得混淆

- 修改变量值、本次补充 → 只影响当前会话，不写配方。
- 写回配方必须是显式动作（「保存本次修改到配方」/「另存为新配方」），并创建新版本。
- 素材库更新不自动覆盖配方内锁定的 `materialRevisionId`；只给非阻断提示。
- 历史快照是提交时事实，后续修改配方不得改变旧历史的显示内容。

依据体验设计 §2.3、规范 `:822`。

### 5.5 选择器

全项目禁用原生 `<select>`（开发规则 `:52`）。比例选择必须显示可理解的横竖/超宽画幅预览，且工作台与设置页共用同一组件。

自绘弹层必须支持方向键、Home/End、Enter/Space、Esc，焦点回归触发元素。

### 5.6 不引入的技术

| 不引入 | 原因 |
|---|---|
| GSAP / framer-motion / 任何 JS 布局动画库 | `motion.css:3` 记录：FLIP 与 `@tanstack/react-virtual` 的绝对定位行冲突。动效用现有 CSS token 体系 |
| 富文本编辑器 / ContentEditable | 开发规则 `:57`。Prompt 是纯文本，语义分段由领域层负责 |
| 新 UI 组件库 | 已有 Radix + 自绘基元覆盖需要 |
| 图标库（除 lucide-react） | 一个字形来源 |

引入任何新运行时依赖前需要单独决策并记入 `DECISION-LOG.md`。

## 6. 令牌纪律

### 6.1 组件不写裸值

组件中禁止出现：

- 裸 hex / rgb 颜色
- 裸圆角像素值
- 裸阴影定义
- 裸时长 / 缓动曲线

必须通过 `--var` 或其 Tailwind 别名。新增视觉值的正确流程：先在 `globals.css` 加变量 → 在 `tailwind.config.ts` 加别名 → 组件消费别名。

例外：`1px` 边框宽度、`0`、布局用的 flex/grid 数值。

### 6.2 密度变量

已有 `--density-*` 系列服务舒适/紧凑双档。新增密集列表必须消费这些变量，不得硬编码高度与间距。

### 6.3 收口清单

v0.2.2 完成时下列项必须归零，作为重构完成的判据：

- [x] 组件中 `backdrop-filter` 出现在 §2.1 之外的位置：0 处
- [x] 组件中直接 `from 'lucide-react'`：0 处
- [x] 组件中裸 hex 颜色：0 处
- [x] `--shadow-md` / `--shadow-elevated` 被组件引用：0 处
- [x] 原生 `<select>`：0 处
- [x] 卡片左侧 accent 强调条：0 处
- [x] 术语表禁用词出现在界面字符串：0 处
- [x] 探索/制作模式开关：0 处（工作台单一对话面）
- [x] `generationMode` 在渲染层被读写：0 处（字段下线）
- [x] 结果卡内嵌第二个 composer：0 处（微调走底部 Composer 微调态）
- [x] 侧栏出现未落库的空对话（点新创作即建空壳）：0 处

## 7. 内容与文案

### 7.1 不伪造

界面上每个字符串必须对应真实信息。禁止：

- 没有数据来源的列表（例：无会话表却显示"最近会话"）
- 编造的统计、遥测、时间戳
- 占位性质的元信息副标题
- 把标准 UI 词换成主题化说法（用"保存"，不用"固化"）

如果去掉一个标签不减少任何信息，就去掉它。

### 7.2 空态是入口

空态必须说明**为什么空**和**下一步做什么**，并提供可点击的动作。禁止只显示插图与"暂无数据"。

三态区分（现状已实现，作为标准）：无前置条件 / 前置条件不完整 / 就绪但无内容。

### 7.3 错误说人话

错误必须说明发生了什么与如何修复，用界面的声音，不道歉、不模糊。失败与取消必须区分——用户主动取消不得显示为失败（开发规则 `:64`）。

必填缺失必须提供 `[定位]` 动作，滚动到字段并聚焦控件。

## 8. 可访问性下限

每张 UI 任务卡的验收必须包含：

- [ ] 焦点环可见（2px `--accent-ring` + 1px offset）
- [ ] 正文对比 ≥ 4.5:1，图标与大字 ≥ 3:1
- [ ] 键盘可完成全流程（Tab / 方向键 / Enter / Esc）
- [ ] 弹层 Esc 可关，焦点回归触发元素
- [ ] 状态不只依赖颜色（图标 + 文字）
- [ ] 图标按钮有 `aria-label`，装饰图标 `aria-hidden`
- [ ] `reduce-motion` 生效
- [ ] 窄屏（641px / 360px）不裁切、不遮挡主要操作

## 9. 验收流程

UI 改动的验证顺序，按开发规则 §6"最小但完整"执行：

1. `npm run check`（typecheck + vitest + build）必须绿。
2. 涉及交互逻辑的加 Vitest；涉及页面流程的加 E2E（`tests/e2e/`）。
3. 桌面（1440px）、临界（1101/801/641px）、窄屏（360px）分别截图验收。
4. 深浅两色各验收一次。
5. 舒适/紧凑两档密度各验收一次（如涉及密集列表）。
6. 用 electron-driver 在真实 Electron 里验收，不只在 Vite preview 里——preload 桥、`media://` 协议、窗口材质只在真实应用中成立。

截图验收不能替代 DOM 断言：本项目 `preview_screenshot` 有已知不可靠性，视觉验证以 `preview_inspect` / `preview_snapshot` 的计算样式与结构为准。

## 10. 变更本文

本文是 UI 层的单一事实源。修改流程：

1. 在 `DECISION-LOG.md` 记录决策与理由。
2. 更新本文对应条目。
3. 如影响视觉规格，同步更新当前版本文档和实际组件。
4. 如影响已完成页面，列出需回改的位置，不留静默不一致。

新增约束的门槛：**必须可检查**。写不出检查方式的规则不要写进本文，写进设计文档的原则章节。
