## 已确认的产品决策

- 用户输入可以叠加在设计方案之上。
- 方案就是 Musefold 中可调用的 Skill；普通界面称“方案”，技术详情和开发文档可以称“Skill”。
- 用户只看到“草稿/正式”两个方案状态；试运行是运行模式，不是第三种状态。
- 草稿不能在普通 Composer 引用；至少一次成功本机试运行并由用户确认后才能设为正式。
- 从 GitHub 安装 Skill 必须经过用户确认。
- 正常 Composer 发送不自动搜索 GitHub；用户必须显式发起“寻找设计方案”。
- 一次对话只允许一个主方案；多个 Skill 必须先合并编译成一个新的组合 Skill/方案。
- 设计方案默认采用“方案主导”优先级；设置中可切换为“用户主导”或“智能协调”。
- 优先级冲突不弹窗、不打断运行。只有安装确认和真正无法执行的系统阻塞才暂停流程。
- 每次运行保存当时的优先级快照、设计方案版本、来源 commit 和 Agent/Provider 版本。
- 设计方案可导出为自包含的私有文件格式，默认离线可复现，不携带密钥和绝对路径。

## 与旧版本的关系

v0.3.1/v3.1 的 GitHub Skill 识别、参考图读取和多图上传研究是输入材料；它们不是 v0.3.2 的数据迁移来源。实现 v0.3.2 时直接创建新的领域模型和存储结构，旧 `recipe` 表、旧配方 IPC 和旧运行时可以删除或留在未加载的历史目录中。
