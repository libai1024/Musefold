> 当前实现入口：[`README.md`](../../README.md)、[`docs/README.md`](../README.md) 与源码组件；v0.2.2 UI 重构文档已归档清理。

## 0. 一页结论

### 品牌

- 英文名：**Musefold**
- 中文名：**未像**
- 品牌读法：英文用于产品、应用和跨语言场景；中文用于中文界面、内容和叙事。两者不是机械音译，而是同一概念的两面。
- 类别：**视觉灵感与 AI 生图工作台**
- 一句话：**把尚未成形的灵感，折叠、展开并变成图像。**
- 对外主标语：`Collect sparks. Shape images.`
- 中文主标语：`让灵感成为图像。`

### 为什么重塑品牌

旧品牌讲的是“如何处理提示词”，偏工具机制和工程过程；`Musefold / 未像` 讲的是用户真正想得到的结果：保存灵感、组织视觉想法、生成并继续发展图片。

改名后，产品可以自然扩展到：

```text
灵感图片 → 参考图 → 视觉想法 → 配方 → 生图 → 编辑 → 历史作品
```

品牌不再被“提示词管理器”或“纯生图客户端”中的任一侧锁死。

### v0.3 的品牌目标

1. 让第一次看到产品的人先理解“这是创意图片工作台”，而不是“一个提示词工具”。
2. 建立独立、清晰的 Musefold 技术身份与 v0.3.0 数据域，不再承接旧品牌兼容层。
3. 让 Logo、应用图标、界面材质和产品文案属于同一个视觉世界。
4. 让 v0.3 图片编辑与参考图能力成为“灵感变成图像”的自然延伸。

## 1. 品牌策略

### 1.1 品牌核心

**核心命题：未像显形。**

很多创作并不是从一条完整提示词开始，而是从一张截图、一个色块、一种构图、一个模糊念头开始。Musefold 的作用不是替用户“写出正确答案”，而是帮助用户把这些不完整的信号暂存、编排、试验和复用，直到它们成为可见的作品。

```text
收集 Collection
    ↓
折叠 Fold
    ↓
显形 Reveal
    ↓
复用 Repeat
```

### 1.2 品牌承诺

> Musefold 让创作者不必在灵感还很模糊时就把它说清楚；先把它留下来，再慢慢让它长成图像。

这条承诺有三个可验证的产品含义：

| 承诺 | 产品证据 |
|---|---|
| 灵感不会散掉 | 本地优先的提示词、配方、图片、作品和历史管理 |
| 想法可以逐步成形 | 制作工作台、参考图、图片编辑、继续微调 |
| 成果下次仍然可用 | 配方、版本、来源追溯、历史快照和导入导出 |

### 1.3 品牌性格

| 维度 | 应该是 | 不应该是 |
|---|---|---|
| 气质 | 安静、聪明、准确、有创作感 | 喧闹、炫技、神秘兮兮 |
| 关系 | 像一张可靠的创作桌 | 像一个替用户做决定的导师 |
| 表达 | 具体、克制、给用户留空间 | 夸大、营销腔、到处写“AI 魔法” |
| 视觉 | 石墨、瓷白、Ember 橙、实色层级 | 霓虹、赛博、彩色渐变、光晕 |
| 动作 | 收集、展开、显形、制作、复用 | 燃烧、爆发、革命、颠覆 |

### 1.4 品牌价值排序

1. **可见性**：让模糊想法获得一个可观察的形态。
2. **可复用性**：一次创作可以沉淀成下一次的起点。
3. **可控性**：用户掌握 Provider、参数、数据和作品归属。
4. **可持续性**：不依赖单一模型、平台或云端账户。
5. **审美秩序**：创作工具本身保持清楚、安静和耐用。

## 2. 定位与用户

### 2.1 对外定位

**Musefold 是一个本地优先的视觉灵感与 AI 生图工作台。**

它把灵感图片、提示词、配方、参考图、生成结果和历史版本放到同一条可回看的创作路径中，帮助个人创作者从“看到一个方向”走到“做出并复用一张作品”。

### 2.2 目标用户

| 用户 | 典型问题 | Musefold 的入口 |
|---|---|---|
| 独立设计师 | 参考图、提示词和不同版本散在多个应用里 | 灵感库、参考图、配方 |
| 内容创作者 | 需要快速试方向，又要保留可复用方法 | 制作工作台、批量探索、历史 |
| AI 生图重度用户 | Provider 多、参数多、复现困难 | Provider 无关、参数快照、历史 |
| 视觉研究者 | 收藏很多，但很难形成自己的结构 | 图片与提示词关联、标签、配方 |

### 2.3 不做什么

v0.3 不把 Musefold 变成以下产品：

- 面向大众的在线图片社区或灵感瀑布流。
- 替代 Photoshop、Figma 或专业修图软件的完整编辑器。
- 绑定单一模型、单一中转站或单一云端账户的生成入口。
- 依靠订阅、社交排名或算法推荐制造留存的内容平台。
- 视觉上充满霓虹、粒子和“AI 魔法”的展示型网站。

### 2.4 核心任务链

```text
发现一张图 / 记下一个想法
        ↓
存入 Musefold，补充上下文
        ↓
从灵感中提取方向或建立配方
        ↓
带参考图和提示词进入制作工作台
        ↓
生成、编辑、微调、比较
        ↓
保存结果，成为下一次创作的资产
```

## 3. 命名与品牌架构

### 3.1 名称含义

**Musefold** 是“灵感被收集、折叠、展开”的动作；`fold` 同时连接了文件夹、折页、层次和展开过程。

**未像** 不是“没有图像”，而是“尚未成为图像”。它强调创作开始前的状态，也给图片、想法、草图、配方和生成结果留出共同的容器。

### 3.2 推荐写法

| 场景 | 推荐写法 |
|---|---|
| 应用名称 | `Musefold` |
| 中文产品介绍 | `Musefold / 未像` |
| 中文界面品牌区 | `未像` 或 `Musefold`，同一界面不要重复并列两次 |
| 文档标题 | `Musefold / 未像 v0.3` |
| 英文介绍 | `Musefold, a visual inspiration and image-making workspace.` |
| 中文介绍 | `Musefold / 未像，一个视觉灵感与 AI 生图工作台。` |
| 版本后缀 | `Musefold v0.3.0` |

### 3.3 产品模块命名

v0.3 先保持已有领域名稳定，避免品牌迁移同时造成产品学习成本上升。

| 当前界面 | v0.3 推荐 | 说明 |
|---|---|---|
| 制作工作台 | 制作工作台 | 保留，直接表达核心动作 |
| 提示词库 | 提示词库 | v0.3.0 保持契约；对外文案可称“灵感库” |
| 配方制作台 | 配方制作台 | 保留，体现可复用结构 |
| 生成历史 | 生成历史 | 保留，强调可追溯 |
| 参考图 | 灵感图 / 参考图 | 界面正文使用“参考图”，品牌文案使用“灵感图” |
| 图片编辑 | 继续编辑 | 入口强调连续创作，不假装是完整修图软件 |
| AI 助手 | 创作助手 | v0.3.1 再评估，v0.3.0 可先保留设置中的“AI 助手” |

### 3.4 命名禁区

默认不使用以下词作为品牌主标题或核心功能名：

`Prompt`、`Forge`、`Studio`、`Magic`、`Genie`、`Canvas`、`AI Art`、`创意引擎`、`魔法`、`灵感魔方`。

原因不是这些词不能出现，而是它们要么过度强调实现方式，要么已经形成明显的行业模板感。`prompt`、`image generation` 等仍可在 SEO、设置和技术文档中作为描述性关键词出现。

## 4. 叙事系统与文案

### 4.1 核心叙事

**短版：**

> 灵感从来不是一条完整的提示词。它可能是一张图、一种光线、一个构图，或者一句还说不清楚的话。Musefold 帮你把这些片段留下来，逐步展开成可见、可改、可复用的作品。

**长版：**

> Musefold / 未像是一张属于创作者的视觉工作桌。你可以收藏图片和灵感，整理提示词与配方，带着参考图进入制作工作台，在不同 Provider 之间生成、编辑和微调，再把每次尝试留下的参数和结果收进自己的创作档案。它不要求你一开始就想得完整，只帮助你把下一个方向看清楚。

### 4.2 信息层级

| 层级 | 文案 | 用途 |
|---|---|---|
| 品牌主张 | 让灵感成为图像 | Logo、官网、应用介绍 |
| 产品承诺 | 收集灵感，展开想法，制作图像 | 首次介绍、商店描述 |
| 功能说明 | 把提示词、参考图、配方和历史放在一条创作路径里 | 功能介绍 |
| 动作语言 | 保存、展开、带入制作、继续编辑、另存为配方 | 界面按钮 |

### 4.3 界面语气

| 情况 | 推荐文案 | 避免文案 |
|---|---|---|
| 空状态 | 从一张图、一段文字或一个想法开始 | 释放你的无限创造力 |
| 首次生成 | 让这个方向先显形 | 开始施展 AI 魔法 |
| 生成中 | 正在让想法显形 | AI 正在全力燃烧 |
| 失败 | 这次没有生成成功，可以检查连接或调整输入 | 生成失败，请重试 |
| 无参考图 | 还没有参考图 | 上传一张图片开启奇迹 |
| 保存成功 | 已加入你的创作档案 | 恭喜你解锁新作品 |
| 继续编辑 | 沿着这张图继续 | 再来一张更好的 |

### 4.4 语气规则

- 句子短，先说发生了什么，再说下一步能做什么。
- 具体描述用户能控制的对象，不把模型拟人化。
- 使用“方向、片段、展开、显形、复用、档案”等词建立品牌语义。
- 不承诺结果必然更好，不使用“完美、颠覆、革命、无限、魔法”等绝对化词。
- 中英文混排时，品牌名保留 `Musefold`，功能名优先中文。

## 5. 视觉身份

### 5.1 视觉论点

> **Graphite / Ember：像一张安静的创作桌，只有正在发生的动作被点亮。**

视觉继续继承 v0.2.2 的 Canon 方向：石墨深色、瓷白浅色、实色表面、薄边框、低阴影、高信息密度。品牌升级不意味着把产品做成营销型落地页；Musefold 首屏应该直接进入可用的创作工作区。

### 5.2 色彩令牌

| 令牌 | 色值 | 用途 |
|---|---|---|
| `Ember 500` | `#D6653F` | 浅色主题主强调色、主要动作 |
| `Ember 400` | `#EF7A52` | 深色主题主强调色 |
| `Graphite 950` | `#18191B` | 深色窗口背景 |
| `Graphite 900` | `#202124` | 深色侧栏、品牌深色表面 |
| `Graphite 800` | `#25272A` | 深色卡片和提升层 |
| `Porcelain 50` | `#F6F6F4` | 浅色窗口背景 |
| `Porcelain 100` | `#EFEFED` | 浅色侧栏 |
| `White` | `#FFFFFF` | 浅色卡片、反白 Logo |

品牌色的使用纪律：Ember 只用于品牌标记、选中、焦点、主动作和需要处理的状态；不用于装饰性卡片、分区标题或大面积背景。

### 5.3 排版

- 界面：沿用系统 UI 字体栈，英文优先使用系统无衬线，中文优先使用 `PingFang SC` / 系统中文字体。
- 品牌字标：先用精细调整的无衬线字标，不引入高对比衬线或装饰字体。
- 正文基准：`13px`；页面标题：`15px`；空态标题最高 `20px`。
- 不使用负字距，不使用随视口缩放的字号，不用超大 Hero 标题压过工作区。
- Wordmark 的 `M` 和 `f` 可以做轻微字形调整，但不能牺牲跨平台可读性。

### 5.4 形状与材质

- 1-2 个核心形体，至少 40% 负空间。
- 主要线宽对应 SVG `viewBox="0 0 100 100"` 中的 `3-4`。
- 开口、切口、折角采用圆润过渡，避免尖锐刀口。
- 通过不对称的折叠和一个偏置圆点制造“正在展开”的张力。
- 内容表面使用实色；阴影只用于 hover 和瞬时层。
- 禁止装饰性渐变、霓虹光、粒子、光晕、赛博网格和玻璃堆叠。

## 6. Logo 系统

### 6.1 推荐方向：Unfolded Frame

Logo 由一个未闭合的折叠画框和一个小圆点组成：画框代表图像边界与收纳，开口代表灵感仍可继续展开，圆点代表尚未成形的创意种子。

这是 v0.3 的主方向，因为它同时满足：图片关联、灵感关联、创作过程关联和小尺寸可识别性。它不依赖“火焰”或“相机”隐喻，能覆盖未来的图片编辑和参考图能力。

### 6.2 六个 Logo 概念方向

| 方向 | 结构 | 语义 | 适用 |
|---|---|---|---|
| A · Unfolded Frame | 未闭合画框 + 偏置圆点 | 灵感展开、图像显形 | **主标、应用图标** |
| B · Seed Orbit | 单一核心圆点 + 不完整轨道 | 一个念头逐渐形成方向 | 生图加载、动效、社交头像 |
| C · Folded Sheet | 两层圆角折页 + 留白切口 | 收集、折叠、复用 | 文档、配方、分享卡片 |
| D · Constellation Path | 2 个主节点 + 1-2 个小节点 | 灵感片段组成创作路径 | 工作流、连接 Provider |
| E · Punched Image | 实心几何体 + 非对称负空间 | 从图像中提取一个方向 | 纯黑白印刷、favicon |
| F · M/F Monogram | 几何化 `M` 与开放 `F` | 品牌字母资产 | Wordmark、小型品牌署名 |

所有方向都必须保持克制：不能把六个语义元素全部塞进一个标志。最终只选一个主标，其他方向作为动效、版式或探索稿，不并行当作多个 Logo 使用。

### 6.3 Logo 组合

| 组合 | 组成 | 主要场景 |
|---|---|---|
| Symbol | 图形标 | 应用图标、favicon、头像、窄侧栏 |
| Horizontal lockup | 图形标 + `Musefold` | 桌面侧栏、网站导航、发布页 |
| Bilingual lockup | 图形标 + `Musefold / 未像` | 品牌介绍、商店、发布说明 |
| Wordmark | 仅 `Musefold` | 页脚、文档、分享卡片 |

### 6.4 使用规则

- 最小数字尺寸：应用图标核心图形在 `16px` 仍可辨识；界面品牌标记不低于 `20px`。
- 安全区：Logo 外围至少保留核心图形高度的 `1/2` 空间。
- 浅色背景使用 Graphite 标志，深色背景使用 Porcelain 标志；Ember 只作为单点或小面积主色。
- 不旋转、不拉伸、不添加外发光、不套渐变、不在标志周围加装饰性圆环。
- 图标底板可以使用圆角方形，但底板必须是实色；不能把 UI 阴影做成 Logo 的固定组成。

v0.3 最终资产需要包含：

SVG 统一使用 `viewBox="0 0 100 100"` 和 `currentColor`，便于浅色、深色和嵌入式场景复用。

Graphite, porcelain and ember palette, flat vector geometry, no ornate lettering, no serif, no futuristic distortion, no extra symbols.

### 7.3 品牌展示背景

首轮展示推荐四种背景：

1. **UI Container**：最贴近桌面应用和产品图标使用场景。
2. **Clinical Studio**：验证 Logo 的比例、边缘和高对比可读性。
3. **Editorial Paper**：承接“未像”的人文、灵感和创作叙事。
4. **Swiss Flat**：验证纯平面、黑白和印刷场景中的稳定性。

展示图必须保持大面积留白、微型排版和产品化语境。禁止使用 Fluid Abyss、LED Matrix 或高饱和 Analog Liquid 作为主品牌背景，它们会把 Musefold 拉向赛博或实验性 AI 品牌。

## 8. 产品体验中的品牌表达

### 8.1 四个动作词

Musefold 的产品动作围绕四个词组织：

| 动作 | 用户理解 | 产品表现 |
|---|---|---|
| 收集 | 把图片、文字和方向留下来 | 导入、保存、标签、关联 |
| 折叠 | 把片段组织成可复用结构 | 配方、素材、来源条 |
| 显形 | 先看见一个可能的方向 | 探索、生成、参考图 |
| 继续 | 在结果上向前一步 | 编辑、微调、分支、历史 |

### 8.2 关键页面文案建议

| 页面 / 状态 | 主文案 | 辅助文案 |
|---|---|---|
| 新用户空态 | 让一个想法先显形 | 从一张图、一段文字或一个方向开始。 |
| 提示词库空态 | 这里放你的创作片段 | 先保存一条提示词，或从制作工作台带入。 |
| 配方空态 | 把一次灵感变成下一次的起点 | 固定规则、变量字段和本次补充可以分别保存。 |
| 制作工作台空态 | 现在想让什么显形？ | 可以直接输入，也可以从提示词库、配方或历史带入。 |
| 参考图上传 | 加入一张参考图 | 它可以帮助你保留构图、材质或氛围方向。 |
| 图片编辑 | 沿着这张图继续 | 描述你想保留、改变或补充的部分。 |
| 生成中 | 正在让这个方向显形 | 结果会自动加入生成历史。 |
| 生成完成 | 这个方向已经有了形状 | 你可以继续编辑、另存或保存为配方。 |
| 生成失败 | 这次没有完成显形 | 检查 Provider 连接、参考图和输入后再试。 |

### 8.3 首次体验

v0.3 Onboarding 不做品牌介绍页，而是让用户直接看到产品的工作方式：

```text
欢迎来到 Musefold / 未像
保存一个方向，制作一张图。

[开始一个想法]
```

随后引导用户配置一个图片生成 Provider；示例输入使用一张参考图和一句短描述，成功后显示“继续编辑”和“保存到创作档案”。品牌价值必须在第一次操作中被体验，而不是靠一段说明文字被解释。

## 9. v0.3 产品与品牌迁移

### 9.1 迁移原则

根据 2026-08-11 的产品决策，v0.3 采用完整品牌硬切换，不建立旧版兼容层：

- Prompt、Recipe、History 的当前数据语义保持稳定，但存储进入独立的 Musefold v0.3.0 数据域。
- Musefold 不读取、不迁移旧应用目录中的数据库、Provider、密钥、图片或本地状态。
- 分享协议、导出格式、Recipe YAML 与数据库文件只接受 Musefold 标识。
- 旧资产不由应用主动删除，但不会被发现、导入或作为回退路径使用。
- 分享卡、导出文件、关于页、日志、诊断和测试标识统一使用 Musefold / 未像。

### 9.2 用户可见迁移清单

| 优先级 | 范围 | v0.3 动作 |
|---|---|---|
| P0 | 应用标题和侧栏品牌 | 全部使用 `Musefold`；中文品牌区显示 `未像` |
| P0 | Onboarding、About、错误提示 | 更新品牌名、产品描述和主标语 |
| P0 | 应用图标 | 使用 Musefold Symbol，重新导出 PNG、ICNS、ICO |
| P0 | 分享卡片 | 署名、纯文字卡和 HTML 模板改为 Musefold |
| P1 | 商店 / README / 截图 | 按新定位重写，不再把“提示词管理”作为第一句 |
| P1 | 设置与导入导出 | 文案、协议、导出格式与 YAML 字段全部改为 Musefold |
| P1 | 参考图和图片编辑 | 使用“灵感图 / 参考图 / 继续编辑”叙事对齐图片编辑主线 |
| P2 | 全量代码字符串 | 清理旧品牌和缩写标识，不保留运行时兼容别名 |

### 9.3 代码与发布标识策略

v0.3 的显示名与技术身份同步收敛：

| 标识 | v0.3 策略 | 原因 |
|---|---|---|
| npm package `name` | `musefold` | 构建与依赖元数据使用新品牌身份 |
| Electron `appId` | `com.musefold.app` | 安装、更新和系统权限采用独立身份 |
| `productName` | `Musefold` | 安装包和系统应用名统一 |
| 应用数据目录 | 仅使用 Musefold v0.3.0 目录 | 不迁移、不回退到旧数据域 |
| export schema | `musefold-export` | 旧品牌格式直接拒绝 |
| YAML / JSON 字段 | 仅接受 `musefold-recipe` 等 Musefold 标识 | 文件交换边界清晰且可测试 |
| 日志和诊断 | 标题、事件、环境变量与诊断编号统一 Musefold | 清除内部旧品牌缩写 |

`productName`、`appId` 和数据命名同时修改。macOS、Windows 验收重点是新数据域首次启动、导入、导出和卸载重装，不执行旧数据读取或迁移测试。

## 12. 验收标准

### 品牌一致性

- [ ] 应用名称、图标、侧栏、Onboarding、About、分享卡片均使用 Musefold / 未像。
- [ ] 产品第一句介绍是视觉灵感与图片创作，不是提示词管理。
- [ ] 标语、动作词和空态文案符合“收集、折叠、显形、继续”。
- [ ] 不出现火焰、锻造、魔法、霓虹、赛博等与新品牌冲突的主视觉。

### Logo 质量

- [ ] 主标只有 1-2 个核心元素。
- [ ] 负空间约占画布 40% 以上，且小尺寸仍有清晰焦点。
- [ ] SVG 使用 `viewBox="0 0 100 100"` 和 `currentColor`。
- [ ] 浅色、深色、黑白、反白四种版本均可用。
- [ ] 16px、20px、32px、128px、512px 五个尺寸没有裁切或粘连。
- [ ] Logo 不依赖渐变、发光、阴影或背景纹理才能成立。

### 产品迁移

- [ ] 旧品牌数据库、图片、Provider、API Key 和备份不会被 Musefold 自动读取。
- [ ] 旧版协议、导出文件和 YAML 会被明确拒绝。
- [ ] Musefold v0.3.0 在 macOS、Windows 使用独立应用身份和数据目录完成首次启动测试。
- [ ] `appId`、协议、schema、数据库、目录和内部标识全部使用 Musefold 命名。
- [ ] `npm run typecheck`、相关单测、构建、E2E 和 package smoke 按改动范围执行。

### 体验一致性

- [ ] 无 Provider、无图片、生成中、失败、取消、重试、部分成功和窄屏状态都有明确品牌语气。
- [ ] 图片编辑主链路可以从已有图片继续，不要求用户重新理解产品。
- [ ] 主要动作仍遵守 v0.2.2 的 accent、实色表面、图标单一导出口和十二态约束。

## 13. 风险与待决策

### 风险

| 风险 | 影响 | 应对 |

| `Musefold` 或 `未像` 存在商标 / 域名冲突 | 高 | 对外发布前完成商标类别、域名、应用商店和社交账号检索；本企划不代替法律清查 |
| 英文名和中文名语义不完全对应 | 中 | 用共同品牌故事连接，不做生硬音译；首次出现并列展示 |
| 改 `productName` 造成数据目录变化 | 高 | 先做稳定目录和迁移测试，再改变安装包显示名 |
| 品牌视觉过度偏编辑工具而弱化 AI 生图 | 中 | 在展示图中同时呈现参考图、工作台和生成结果；不使用纯 Logo 叙事作为唯一产品证据 |
| 旧用户认为只是改名 | 中 | 发布说明明确“能力扩展为灵感、参考图、编辑和可复用创作档案” |

### v0.3 必须决策

## 14. 成功判断

v0.3 品牌不是以“Logo 换了”为完成，而是满足以下结果：

1. 新用户能在第一次打开时理解这是一张视觉创作工作桌。
2. 用户可以从一张参考图或一句模糊想法开始，而不是先学习提示词术语。
3. 生成结果、编辑结果、提示词和配方可以进入同一个创作档案。
4. 视觉身份在 16px 图标、深色工作区、浅色设置页和分享卡片上都成立。
5. 新安装和升级安装都进入独立的 Musefold v0.3.0 数据域，不隐式加载旧版状态。

这份文档是 v0.3 的品牌事实源。后续视觉实现、文案改动和发布资产应回链到这里；如果实现需要偏离，应先记录决策和兼容影响，再修改代码。
