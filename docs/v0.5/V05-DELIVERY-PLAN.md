# V05 · 实施计划与验收

> **状态**：设计规格（待评审）
> **节奏**：三阶段约 4 周（P1 一周半 / P2 一周半 / P3 一周），每阶段硬出口标准，未达标不进下一阶段。
> **纪律**：延续 v0.2 开发规则与 v0.4 惯例——契约先行（golden 测试先冻结再写业务）、每卡带验收、桌面全量单测 + E2E 一条不删是每阶段门禁。
> **并行性**：V05-SRV-\*（服务器）与 V05-ACC-\*（App 内核）可双线并行：内核开发用本地 docker new-api 联调，不阻塞在云服务器交付上。

> **实现快照（2026-08-13）**：V05-SRV-01~05、V05-ACC-01~05、V05-UI-01~06 已完成；`npm run typecheck`、1049 条 Vitest、完整真实 Electron E2E（231 passed / 20 skipped）与生产构建均通过。P3 三平台手工矩阵、发布文档冻结与正式 tag 尚未执行。

## 4. 开放问题（P1 冻结，冻结后回写各文档）

> 2026-08-13 生产服务器（new-api v1.0.0-rc.24）实测冻结，证据见冒烟脚本 `/opt/musefold/configure-stage*.py` 输出。

| # | 问题 | 状态 | 冻结结论 |
|---|---|---|---|
| OQ-01 | 令牌明文取回可行性 | ✅ 已冻结 | 列表/详情接口返回**掩码** key；完整 key 经 `POST /api/token/{id}/key`（带限流）获取。App 可安全复用设备令牌（按 id 取回） |
| OQ-02 | 额度不足错误结构 | ✅ 已冻结 | HTTP 403 + `error.code = "insufficient_user_quota"`（`error.type = "new_api_error"`）→ 映射 `ACCOUNT/QUOTA`。另：未定价模型为 HTTP 400 + 中英文提示。注意：充值后配额有 **~15–60s Redis 缓存延迟**，App 兑换成功文案需容忍短暂延迟（"额度已到账，稍候生效"） |
| OQ-03 | 余额展示换算（quota → 点） | ✅ 已冻结 | 服务器 `QuotaPerUnit=500000`（= $1）；App 展示按 quota/500000 换算为"额度单位" |
| OQ-04 | 功能品牌名（候选「云契」）| 🔶 待定 | 文案暂用「账号」 |
| OQ-05 | 官方域名与备案路径 | ✅ 部分冻结 | 已选**香港免备案**（45.207.211.136 已上线，LE 裸 IP 短效证书）；正式发布前仍建议绑定域名（迁移韧性），域名待运营者购买 |
| OQ-06 | access_token 生命周期语义 | ✅ 已冻结 | rc.24 登录返回 **JWT**（约 30 分钟）+ **`new_api_refresh` Cookie**（约 30 天、HttpOnly、每次续期轮换）；`POST /api/user/auth/refresh` 已实测无 Origin 头可用 → App 可静默续期 30 天，无需存密码、多设备互不干扰。管理请求 `Authorization: Bearer <JWT>`，无需 `New-Api-User` 头（该头仅"系统 access token"模式需要，App 不采用） |
