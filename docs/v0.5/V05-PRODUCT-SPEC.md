## 1. 信息架构变化

```text
设置
├── 账号            ← 新增，导航首位（FR-SET-01）
├── 服务商（生图）    ← 列表新增「账号托管」条目形态（FR-SET-04）
├── AI 连接（文本）   ← 同上
└── …（其余不变）

Onboarding（首启引导）
步骤 1 欢迎 → 步骤 2 配置方式（双轨，改造）→ 步骤 3 校验 → 步骤 4 首图
                    ├── 2A 账号轨：登录/注册 →（额度为 0）2A' 兑换码
                    └── 2B 高级轨：预设 + Key（既有流程）

创作台 / 配方助手错误卡
└── 新增三类可行动错误：重新登录（ACCOUNT/AUTH）、输入兑换码（ACCOUNT/QUOTA）、
    刷新模型列表（ACCOUNT 下的 model_not_found，FR-ERR-05）

历史 → 成本看板（CostDashboard）
└── 账号模式适配：余额卡、点单位记账、真值化标注（§9）
```

原则：**账号是一层"自动配置"，不是新的平行系统**。所有账号产物（托管记录）都出现在用户熟悉的既有列表里，可检视、可切换激活，只是不可手改。

## 2. 设置 → 账号面板

### 2.1 四态规格（FR-SET-01）

| 状态 | 判定 | 面板内容 | 主动作 |
|---|---|---|---|
| **未登录** | `status.loggedIn = false` | 登录/注册双 tab 表单；副文案说明"登录后文本与生图自动配置" | 登录 / 注册 |
| **已登录 · 正常** | `loggedIn && health='ok' && quota>0` | 用户名、余额（含刷新按钮 + 「约可生成 N 张」副文案）、**服务器公告区**（FR-SET-05：未读公告卡片式展示，已读折叠，本地记忆）、本设备令牌名与后缀、服务器地址（只读摘要）、「兑换码」折叠入口 | 登出（次要、带确认） |
| **已登录 · 额度为零** | `quota = 0` | 同上，余额区替换为醒目的兑换引导卡：「余额为 0，输入兑换码开始创作」 | 兑换 |
| **凭据失效** | `health = 'token-invalid'` | 状态横幅「登录状态已失效」+ 原用户名；表单预填用户名 | 重新登录 |

服务器不可达（`health='unreachable'`）不单列状态：在当前态上叠加一条非阻塞横幅「无法连接账号服务器」+ 重试按钮（FR-ERR-03）。

### 2.2 登录 / 注册表单

- 字段：用户名、密码（注册 tab 增加"确认密码"）。无邮箱、无验证码（D4）。
- 校验：用户名 3–30 字符、密码 ≥ 8 位（OQ 冻结后与服务器一致）；错误就地内联展示。
- 提交中：按钮进入 loading，表单锁定；编排各阶段更新进度文案（「验证账号…」→「配置 AI 服务…」）。
- 注册成功即登录（US-01），不要求二次输入。
- 忘记密码：链接文案「忘记密码？联系管理员重置」，点击打开帮助说明（含联系方式占位，OQ-05 定稿后填入）。

### 2.3 高级折叠区（FR-SET-03）

- 服务器地址：只读展示 + 「修改」。修改流程：弹确认（"更换服务器将退出当前账号"）→ 登出 → 输入新地址（URL 校验）→ 回到未登录态。
- 「打开网页控制台」：系统浏览器打开 `<服务器>/console`（令牌管理、改密码等高级操作去网页做，App 不复刻）。

### 2.4 余额展示

- 展示为「点」+ 相对语义辅助文案（换算规则 OQ-03 冻结后统一）。
- 刷新时机：面板打开、登录成功、兑换成功、手动点击刷新（FR-ACC-06）。刷新失败保留旧值 + 时间戳提示。

## 3. Onboarding 双轨

### 3.1 步骤 2 · 配置方式选择（FR-OB-01）

两张选择卡，账号轨在前并带「推荐」角标（沿用预设卡的 recommended 角标形态）：

| 卡 | 标题 | 副文案 |
|---|---|---|
| 账号轨 | **登录 Musefold 账号** | 一次登录，文本与生图自动配置，无需 API Key |
| 高级轨 | **使用自己的 API** | 连接自备服务商或自建中转站（OpenAI 兼容） |

服务器不可达时账号卡置灰 + 提示「账号服务暂不可用，可先使用自己的 API」（FR-ERR-03）。

### 3.2 账号轨流程（FR-OB-02/03/04）

```text
2A 登录/注册（双 tab）
   │ 成功（编排完成：令牌 + 双栈托管就绪）
   ├─ quota > 0 ──────────────→ 3 校验
   └─ quota = 0 → 2A' 兑换码 ──→ 3 校验
                    └─「暂时跳过」→ 直接完成引导进入主界面（保留额度提示）
3 校验（自动开始）：文本 ✓ · 生图 ✓ · 余额 N 点     ← 并行执行，逐项打勾
4 首图：既有流程不变（示例提示词 + 比例/质量）
```

- 2A' 兑换码步：单输入框 + 「兑换」；成功态展示「+N 点已到账」后自动前进；失败就地报错（见 §6 文案表）。「暂时跳过」为次要链接——不阻断用户探索主界面，额度提示由账号面板与生成错误闭环兜底。
- **到账延迟（服务端实测约 15–60s 缓存）**：兑换成功后账号面板余额立即更新（管理面无延迟），但生成调用可能短暂仍报额度不足——错误卡在"兑换成功后 60s 内的额度错误"场景下文案改为「额度生效中，请稍候重试」，重试按钮常显；Onboarding 兑换步到校验步之间的自动校验若因此失败，自动间隔 15s 重试至多 4 次后才展示错误。
- 步骤 3 任一项失败：展示该项错误与「重试」，不阻塞另一项；生图校验失败但文本成功时允许「先进入应用」（次要动作）。
- 步骤 4 与既有 `generateFirstImage` 流程一致（走托管 Provider）。

### 3.3 高级轨（FR-OB-05/06）

- 保留既有「预设 + Key → 校验 → 首图」流程与全部行为（含 E2E 门控、`forceShow` 测试钩子）。
- 网关类预设（TvT / New API / LiteLLM / 自定义）的 Key 输入下方新增勾选：**「同时用于文本 AI（配方助手等）」**，默认勾选；悟空生图组预设不显示。
- 勾选后保存动作额外创建文本连接（同 baseUrl、文本兜底模型、同一 Key 写入文本 keychain）并激活；步骤 3 校验双栈（形态同账号轨）。

### 3.4 状态机扩展（`src/features/onboarding/store.ts`）

新增字段（产品语义，命名实现时定）：

| 字段 | 语义 |
|---|---|
| `track: 'account' | 'byok' | null` | 步骤 2 选择的轨道；null = 未选择 |
| `accountForm: { mode: 'login' | 'register', username, password, confirmPassword }` | 2A 表单态（密码字段不持久化、不进日志） |
| `accountBusy / accountError` | 编排进行中与错误展示 |
| `quota: number | null` | 登录后余额，决定是否进入 2A' |
| `redeemCode / redeeming / redeemResult` | 2A' 兑换态 |
| `alsoConfigureText: boolean` | 高级轨"一份 Key 配两栈"勾选（默认 true，悟空隐藏） |
| `validation2: { text: Result | null, image: Result | null }` | 步骤 3 双栈校验结果 |

既有字段（`presetId/apiKey/providerId/validation/...`）语义不变，服务于高级轨。

## 4. 托管条目展示（FR-SET-04 / FR-GW-03）

在「服务商」与「AI 连接」两个列表中：

- 托管条目名称固定「Musefold 账号」，带徽标 `账号托管`；副行显示服务器域名 + 当前模型。
- Key 区域显示「由账号管理 · 令牌 ····{suffix}」，无「修改 Key」入口。
- 「编辑」对话框内：baseUrl 只读、模型可改（下拉数据来自 `listModels`）、无删除按钮；底部说明「此配置随账号自动管理，登出后移除」。
- 手动条目一切如旧；激活切换在两类条目间自由进行（FR-GW-05）。

## 5. 错误闭环总表（FR-ERR）

| 场景 | 错误码 | 用户所见 | 动作 |
|---|---|---|---|
| 生成/文本调用返回 401（托管记录） | `ACCOUNT/AUTH` | 「账号令牌失效，重新登录即可恢复」 | 主：重新登录（跳账号面板/内联表单）；重登成功自动重供给令牌 |
| 生成/文本调用额度不足 | `ACCOUNT/QUOTA` | 「余额不足，本次生成未执行」 | 主：输入兑换码（内联弹窗）；兑换成功显示「重试」 |
| 登录失败（凭据错误） | `ACCOUNT/CREDENTIALS` | 「用户名或密码不正确」 | 表单内联，密码清空 |
| 注册失败（用户名占用） | `ACCOUNT/CONFLICT` | 「该用户名已被使用」 | 表单内联 |
| 兑换失败（码无效/已用/空，服务器统一模糊响应防枚举） | `ACCOUNT/REDEEM_INVALID` | 「兑换失败，请检查兑换码后重试」 | 表单内联；无法区分具体原因（实测服务器对所有失败返回同一响应） |
| 服务器不可达/超时 | `ACCOUNT/NETWORK` | 「无法连接账号服务器，请检查网络后重试」 | 重试；Onboarding 提示可走高级轨 |
| 服务器 5xx | `ACCOUNT/SERVER` | 「账号服务器开小差了，请稍后重试」 | 重试 |
| 对托管记录做被禁操作 | `ACCOUNT/MANAGED_READONLY` | 「此配置由账号管理，登出后可移除」 | 无（提示即闭环） |

非托管记录（BYOK）的既有错误映射（`AUTH/401`、`RATE_LIMIT/429`、`MODEL`、`SERVER/5xx`）完全不变。

## 7. 边界场景

| # | 场景 | 行为 |
|---|---|---|
| E1 | 离线启动 | 账号面板展示缓存态（用户名/最后余额 + 「上次更新」时间）；调用时按 `ACCOUNT/NETWORK` 闭环 |
| E2 | 登录编排中途失败（如令牌创建失败） | 整体回滚（NFR-REL-02），面板回未登录态并展示具体阶段错误；重试从头执行 |
| E3 | 令牌在网页端被删除 | 下次调用 401 → US-05 闭环；重登时按 FR-ACC-07 新建令牌 |
| E4 | 用户在网页端改密码 | 设备令牌通常仍有效（调用不断）；access_token 失效 → 面板 `token-invalid` 态，重登恢复 |
| E5 | 额度在生成过程中耗尽 | 该次生成失败 → `ACCOUNT/QUOTA` 闭环；历史记录按既有失败语义落账 |
| E6 | 多设备同账号 | 各设备独立令牌互不影响；余额共享（服务器侧扣减） |
| E7 | 重装 App | 账号 store 与 keychain 条目随系统残留策略而定；重登即重建；旧设备令牌可在网页端清理 |
| E8 | 服务器整体迁移域名 | 用户改高级项地址 → 强制登出重登；文档提示运营者做旧域名 301 过渡 |
| E9 | 同时登录 + 手动配置指向同一服务器 | 允许（两条记录、两个 Key）；不做去重，切换激活即可 |
| E10 | E2E harness（`musefold_e2e=1`） | 双轨 Onboarding 沿用既有门控（默认不弹，`forceShow` 显式打开）；账号轨用 mock 服务器 fixture |

## 8. 成本看板（账号模式适配，FR-COST）

既有 `CostDashboard.tsx`（历史 → 成本看板对话框）保持整体结构（时间范围/分组切换、柱状分布、Provider 明细），账号模式下做四处适配：

### 8.1 余额卡（FR-COST-01）

- 已登录时，汇总区从三卡变四卡，首位插入「账号余额」：主值 `N 点`，副文案 `约可生成 M 张`（M 由主进程按当前生图单价换算，`AccountStatus.estImagesRemaining`）；未登录时不出现，保持三卡。
- 打开看板触发一次余额刷新（与账号面板的刷新共用节流）。

### 8.2 单位与聚合（FR-COST-03）

- 托管 Provider 的消费以「点」记账与展示（`20,000 点` 格式，千分位）；BYOK 记录维持 `¥X.XX`。
- 「累计花费」卡在两种单位并存时双行显示（上行点、下行 ¥）；单一来源时单行。
- 柱状图与 Provider 明细行金额随各自单位渲染；混合单位的时间桶内按单位分色堆叠（实现允许简化为并列双柱）。

### 8.3 真值化标注（FR-COST-02）

- 托管 Provider 明细行尾缀「账号计费」徽标。
- 免责声明按在场来源变体：仅 BYOK = 现文案不变；仅托管 = 「托管服务商成本按账号实际计费单价统计，与服务器扣费一致」；混合 = 两句并列。
- 「配置单价」按钮：BYOK 在场时保留（跳服务商设置）；仅托管时替换为「查看账号」（跳账号面板）。
- 托管 Provider 永不触发"未配置单价"黄条（单价随账号自动同步）。

### 8.4 边界

- 登出后：历史中的托管消费记录保留且仍按「点」正确显示（单位随记录快照，FR-COST-03）；余额卡消失。
- 定价同步尚未完成的短窗（登录后首次拉取前）：该窗口内的生成记录按当时已知单价入账，不回溯改账。

## 9. 刻意不做的产品决策

- 不做 App 内改密码 / 改用户名（网页控制台已有，避免双实现）。
- 不做余额低于阈值的主动提醒（无后台轮询；额度状态在动作点自然暴露）。
- 不做账号轨的"记住密码/自动填充"——密码不落盘是硬约束，系统钥匙串自动填充能力交给 OS。
- 不做游客模式的"临时额度"——零额度即引导兑换，规则单一。
