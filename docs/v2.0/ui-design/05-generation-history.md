# 05. 生成历史

## 1. 页面定位

生成历史是结果资产的回看、筛选、比较和再利用中心。它要同时满足：

- 快速扫描大量生成记录。
- 找到某次生成的完整参数。
- 打开大图。
- 继续微调。
- 保存为提示词。
- 加入设计方案。
- 查看成本和磁盘使用。

## 2. ZCode 对比截图

![ZCode 已有任务和右侧上下文面板](./references/zcode/zcode-mainview-dark.jpeg)

继承：

- 中央内容与右侧 Inspector 分栏。
- 右侧面板不覆盖中央内容。
- 顶部工具条承载页面级操作。

替换：

- ZCode 的任务和工具输出换成图像记录。
- 右侧文件面板换成生成详情。
- 任务状态换成生成状态、模型、成本和保存状态。

## 5. Page Header

组件：

- 标题与记录数量。
- 刷新。
- 成本看板。
- 磁盘占用。
- 清理菜单。
- Inspector 展开/收起。

规格：

- 高度 48-56px。
- 标题 18px / 600。
- 页面主动作最多一个。
- 成本看板使用 outline/subtle，避免与生成按钮竞争。
- Inspector toggle 使用 icon button，必须有 tooltip。

## 6. Filter Bar

筛选维度：

- 状态：成功、失败、排队、取消。
- 时间范围。
- 模型或服务商。
- 画幅。
- 来源：新设计、设计方案、提示词库。
- 是否已保存或已加入方案。

布局：

```text
┌───────────────────────────────────────────────────────────┐
│ [搜索] [状态 ▾] [时间 ▾] [模型 ▾] [来源 ▾]   已筛选 3 项 [清除] │
└───────────────────────────────────────────────────────────┘
```

Light：Filter Bar 使用 raised surface。

Dark：使用 `--bg-elevated`，选择项用 accent soft。

筛选选择器的圆角 8px，标签 chip 6px，不使用过多 pill。

```text
├────────────────────────────┤
│ 状态：已完成                │
│ 生成时间 / 模型 / 成本      │
├────────────────────────────┤
│ 提示词                      │
│ ...                         │
├────────────────────────────┤
│ 参数                        │
│ 比例 1:1 质量 ...           │
├────────────────────────────┤
│ [继续微调] [存为提示词]     │
│ [加入方案] [下载]           │
└────────────────────────────┘
```

Light：Inspector 使用 Sidebar surface，图片区域使用 white media surface。

Dark：Inspector 使用 `#1b1c1f`，图片区域使用 `#2a2c30`。

细节：

- Dock 宽度 320px 左右。
- 图片最大宽度为 Inspector 内容宽度减去 24px。
- Inspector 内 section 之间 16px。
- 内容分隔采用 section heading，不给每个字段包卡片。
- 长提示词默认显示摘要，点击展开。

## 9. Status Presentation

| 状态 | 图标/文字 | 操作 |
| --- | --- | --- |
| queued | 排队中 | 取消 |
| running | 生成中 | 停止 |
| succeeded | 已完成 | 打开/复用 |
| partial | 部分完成 | 重试失败项 |
| failed | 生成失败 | 查看错误/重试 |
| cancelled | 已取消 | 重新生成 |

颜色：

- success 使用绿色。
- warning 使用黄色/棕色。
- danger 使用红色。
- Ember 只表示当前操作和运行强调，不替代错误颜色。

## 10. Image Lightbox

Lightbox 是媒体级 Dialog：

```text
scrim
┌─────────────────────────────────────────────┐
│ [关闭]                             [下载]    │
│                                             │
│                  image                      │
│                                             │
│ [上一张]                               [下一张] │
└─────────────────────────────────────────────┘
```

规格：

- 16-20px 圆角。
- Light scrim `rgba(20,20,24,.42)`。
- Dark scrim `rgba(0,0,0,.72)`。
- 图片不强制铺满屏幕，保持原比例。
- 关闭、上一张、下一张、下载均有 icon button 名称。
- 键盘支持 Escape、Left、Right。

## 11. Cost Dashboard

成本看板为局部 Dialog 或 sheet，不进入页面永久主列：

- 总成本。
- 按模型分布。
- 按时间分布。
- 任务数。
- 失败/重试统计。

Light：白色数据 surface + subtle border。

Dark：`#25272a` 数据 surface + 低对比分组。

图表不要使用紫色渐变；使用 Graphite、Ember、success、warning 的语义色。

## 12. Disk Usage / Cleanup

- 磁盘占用显示当前使用量和可清理项。
- 清理菜单区分缓存、失败结果、回收站。
- 可恢复删除与永久清理文案不同。
- 永久清理必须进入确认 Dialog。

## 13. Empty / Error

### Empty

```text

```

### Filter Empty

```text

```

### Error

列表错误提供刷新；单条生成错误提供重试；图片路径错误提供重新定位或隐藏损坏项。

## 14. ZCode 借鉴与差异

借鉴：

- 主内容与右侧详情分栏。
- 顶部页面级动作。
- 行 hover 承载低频操作。
- 可独立关闭右侧面板。

差异：

- 生成历史的主对象是图片，不是文本任务。
- Inspector 要支持“继续创作”，不是只读查看。
- Lightbox 是核心工作流，不是附属预览。
- 成本和存储是 Musefold 专属的资产管理信息。

## 15. 验收

- [ ] 历史列表可以快速比较图片、状态和摘要。
- [ ] Inspector 真实占列，不覆盖列表。
- [ ] 继续微调、保存提示词、加入方案在详情内可发现。
- [ ] Lightbox 具备完整键盘和按钮操作。
- [ ] 成本、存储和清理不破坏主历史工作流。
- [ ] Light/Dark 的图片承托面有清晰层次。
- [ ] 空状态、筛选空状态、错误和失败结果完整。

## 16. 本轮讨论确认的历史定位

生成历史是结果资产的回看、筛选、比较和再利用中心，不是单纯的时间记录页面。

```text
查看结果
→ 比较结果
→ 查看完整参数
→ 打开大图
→ 继续微调
→ 保存为提示词
→ 加入设计方案
→ 下载或删除
```

与 ZCode 的区别：

```text
ZCode：回看任务和工具执行过程
Musefold：回看图片、提示词和生成参数
```

历史页面以图片为一级对象，同时保持高密度扫描能力。

## 24. 生成状态细节

| 状态 | 视觉表达 | 动作 |
| --- | --- | --- |
| 排队中 | warning/neutral + 排队中 | 取消 |
| 生成中 | Ember/进度状态 | 停止 |
| 已完成 | success + 已完成 | 打开/复用 |
| 部分完成 | warning + 部分完成 | 重试失败项 |
| 失败 | danger + 失败 | 查看错误/重试 |
| 已取消 | tertiary + 已取消 | 重新生成 |

状态不能只依靠颜色：

```text
图标 + 文案 + 颜色
```

Ember 只表达“正在进行”或当前动作，不能替代 success 和 danger。

## 28. 与 ZCode 的语义转换

```text
ZCode 任务列表        → Musefold 生成历史列表
ZCode 任务详情        → Musefold 生成详情 Inspector
ZCode 文件/工具输出   → Musefold 图片和参数
ZCode 继续任务        → Musefold 继续微调
ZCode Fork            → Musefold 新建变体/方案
ZCode 右侧 Dock       → Musefold 历史详情 Dock
```

Musefold 历史页面必须比 ZCode 更突出图片，但不能变成没有文本信息的作品画廊。

## 29. 本轮历史决策

### 29.1 历史主列表

推荐：

```text
图片缩略图 + 提示词摘要 + 状态 + 时间
```

不推荐纯图片瀑布流，因为用户需要比较模型、参数、来源和生成状态。

### 29.2 Inspector 默认状态

推荐：

```text
默认收起
用户选择历史记录后展开
```

首次进入时提供最大列表宽度，选择结果后再展示详细上下文。

### 29.3 Lightbox 层级

推荐：

```text
Lightbox 只负责看图
继续微调、保存提示词、加入方案放在 Inspector
```
