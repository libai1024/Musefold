# Musefold v2.5.1

v2.5.1 是 v2.5 的收口补丁版本。它不新增产品功能，交付的是 v2.5「一次开发，四端复用」迁移的**完整验收**。v2.5 的成果目前处于三种状态：已实现、已局部部署、已实测但未提交；它们也没有在同一份源码上验收过。本版本要把这些成果推进到四个条件都成立：

1. 只有一份已提交的源码；
2. 这份源码上跑过一整套门禁；
3. 完成一次从零开始的真实付费链路；
4. 留下一份可审阅的证据。

之后才进入 Windows、签名公证、远端 CI 与正式发布。

**当前状态（2026-09-23）**：本文是一次只读审计的结果，审计期间没有运行门禁、没有产生费用、没有改动源码。
- **任务包与验收**：任务包完成 93/98，有 5 个父项未勾选；spec 的 MVP 共 7 项，只勾选了 1 项；检查清单为「部分通过」；任务包校验脚本判定「验收未通过」。
- **09-21 最后的源码**：1898 项 `54a8362b…`（16:17）。它比上一份候选 `6fb42ed5…` 只多改了 3 个文件：共享工作台 `GenerationTimeline.tsx`、它的就地测试 `workbench-multi-image.test.tsx` 和 `tests/v25/web.workbench.spec.ts`。修的是 16:06 从零付费轮（paid-22）暴露的缺陷：成图后、图片字节到达前，图片没有保留可见尺寸。
  - `54a8362b…` 没有跑过任何统一门禁，只有定向证据：就地单测从 18P/4F 修到 22P，E2E 只有修复前的 2F 红灯。
  - `6fb42ed5…` 跑过 check 38/38、Provider 8P、满额登录 2P，以及没有登记进 09-21 记录的根测试复跑 3321P/77S、条件项 27P/43P 和 Worker 349P/2S。

## 核心结论

v2.5 的产品功能基本都已实现。09-21 的 ui-parity 核对表里，所有产品面都有实现和就地/三形态测试。下面几项也都有逐段证据：
- 设计方案全链路、账号多模型与云端权威价格；
- 真实跨端同步、登录会话管理；
- 完整资产 GC（阶段 4 开发）、费用 SP-P4 和 SP-P5 的大部分。

真正没完成的是下面五件事：

1. **没有「同一源码上的完整验收」**。最后一次全绿是 09-20 的 1850 项 `bb580e98…`，它只能证明当时的输入。09-21 之后的门禁分散在多份源码上：

## 0. 定位与原则

- **权威顺序**：源码、迁移和自动化测试优先，其次是 `docs/v2.5` 的四份基线文档（架构、交付计划、数据迁移、UI 规范）。本文是清单，不是新规范；如果与代码冲突，以代码为准，并修正文档。
- **证据纪律**（沿用 v2.5）：
  - 每个结果都必须绑定源码清单摘要或提交号；
  - skip 不算通过，mock 不算实网，源码构建不算安装包；
  - 首次失败必须留证；接续运行不能替代从零运行；
  - 已经发生的收费请求只能做只读恢复，不重发。
- **红线**（沿用 CLAUDE.md）：
  - 密钥只能放在主进程 `safeStorage` 或服务端；
  - 版本号不在功能提交里改；
  - 暂缓域不顺手实现，也不删除；冻结面不动；
  - 单文件不超过 3000 行；
  - 提交格式为 `type(scope): subject`；
  - 新代码带就地 `__tests__/`；不删测试换取门禁变绿。
- **外部动作需要逐次授权**：提交、推送、部署、收费调用、改动账号服务，都需要用户逐次明确授权。本文不构成任何授权。
- **不复制敏感信息**：本文不复制任何口令、Key、token、主机地址、账号服务域名或账号名。真实账号一律称为「用户指定的真实账号」。已有的授权口径是：用户授权使用指定真实账号的现有积分完成验收，没有额外的总额上限，也不自动充值。

   - Toaster 按规范改，还是登记为差异；
   - 演示页、logo 文件、旧部署脚本如何处置；
   - 桌面保留政策；
   - 托管文本和真实账单的范围。
2. **会改源码的修复**：
   - 提交 CLI/MCP 修复（P0-01）；
   - Toaster（P0-08）；
   - 网络归因之后的修复（P0-07）；
   - 演示路由处置（P0-10）；
   - 同时完成 P0-13 的文档修正。
3. **冻结候选提交**：生成 `v25-build-manifest`。此后所有结果都绑定这个提交；如果再改源码，就重新冻结，并从受影响的门禁开始重跑。
4. **在同一提交上跑门禁**：`pnpm run check` → 完整 API/Worker → `pnpm run build` + 三形态 E2E → 自然一小时 → macOS 包链。
5. **真实环境验证**：
   - 真实 macOS 窗口验证（P0-09）；
   - L166 的真实重登、双宿主核对（P0-08）；
   - 从零完整付费轮（P0-06）；
   - 余额对账（P0-11）。
6. **生产对齐**：按最终提交重新部署（需授权），或给出一致性证明；完成配置核对表（P0-10）。
7. **关闭**：勾选 5 个父项、MVP、检查清单，登记 manifest（P0-12）。至此非 Windows 收口完成。
8. **P1**：Windows → 签名公证 → 远端 CI → 真实旧库与包内迁移 → 发布与回滚演练 → 公共站点切换 → Changesets + tag。

命令矩阵（沿用 CLAUDE.md，交付前必须全绿）：

| 改动类型 | 必跑 |
|---|---|
| 任何源码 | `pnpm run check`（Biome、typecheck、单测、双端 build、depcruise 边界） |
| features / ui / 双端屏幕 | 另跑 `pnpm run test:e2e`（Web 桌面/移动视口 + Electron，含视觉快照） |
| 桌面主进程 / IPC / 数据 | 先 `pnpm run build`，再 `pnpm exec playwright test -c tests/v25 --project electron` |
| SQLite schema | `packages/desktop-db` 迁移流程（见 `apps/desktop/AGENTS.md`，迁移必须内联进主进程 bundle） |
| PG schema | `pnpm run db:migrate` + api/worker 单测，遵守 expand/contract 纪律 |
| 打包产物 | `pnpm run package:mac:adhoc`，之后跑 package-smoke |

完整 API/Worker 集成、自然期限和真实账号流程的具体命令，见[测试手册](../v2.5/V25-MIGRATION-TESTING.md) T0–T5 和[测试续篇](../v2.5/V25-MIGRATION-TESTING-CONTINUED.md)。

**v2.5.1 非 Windows 收口**：以下全部成立才算完成。

6. §1 到 §3 中过期的文档描述都已修正；本文状态行更新为「已收口」。
