# UI 审计:工作台(Workbench / Composer / 时间线)

> 只读审议。截图:`workbench-empty.png`、`workbench-finished.png`,以及 Windows 真机流程 `09-model-menu-open.png`、`10-prompt-typed.png`、`11-generating.png`、`13-generation-complete-full.png`。

## 总体评价

本轮走查后工作台已相当接近目标语法:右簇「模型 pill + 微刷新 + 发送」的 Codex 式收敛、建议词胶囊、聚焦光环都到位。剩余问题集中在**完成回合的动作区与费用核对的排版**、**空态水印的视觉权重**。

## 发现

### W1(高)完成回合底部三行「费用核对」文字区排版失衡
- 截图:`13-generation-complete-full.png`。出图卡下方是三行左对齐小字:「图片已保存,费用仍需核对。/ 费用尚未核对完成,未知道金额不会记作零。/ [核对原任务]」。
- 问题:①两条说明语义重叠(都是「费用还没定」),占两行;②纯文字+独立按钮没有容器,视觉上像误排的段落而非一个状态组件;③与「已完成 · musefold-image-pro」头部的胶囊语法断裂。
- 建议:合并为一行状态条 `待核对 · 费用以云端结算为准 [核对原任务]`(secondary 胶囊 + 行内 text-link),与 Badge 体系对齐。

### W2(中)空态品牌水印字重过高
- 截图:`09-model-menu-open.png`。背景「Musefold」大字水印 + 图标,视觉重量压过建议词;建议词本身 opacity 渐隐(设计如此)但水印使中间区显得「满」。
- 建议:水印透明度降一档(约 4% → 2.5%),或上移留白,让建议词成为第一读点。

### W3(中)生成中状态缺可感知的行内反馈
- 截图:`11-generating.png`。发送后时间线尚无任何内容(首图未落第一格),只有发送钮变「停止」;用户不知道已受理。
- 建议:受理后立即渲染 pending 卡(骨架/进度占位),而非等首个事件;「已提交,等待云端受理」一行小字也可。

### W4(低)比例钮「auto 自动」语义重复
- Composer 工具栏:`auto · 自动` 同时出现缩写与全称,信息冗余;其余钮(「标准」「反向词」)是纯文字。
- 建议:静息显 `auto`,全称进 title(与其余 tool-btn 的 title 语法一致)。

### W5(低)完成回合的四个动作图标(复制/收藏/下载/删除)没有 tooltip 记录
- 截图:`workbench-finished.png` 图卡下缘四枚 ghost 图标。代码里是 icon-only;若已带 title 则达标,但截图无法确认——按「icon 必须有 title」红线登记待核。
- 建议:逐一确认 `title` 存在;缺失即补(这是 icon 替代文字的必要条件)。

### W6(信息)发送钮双态(↑/停止)形态已达标
- 方案域多处测试钉死的「禁用并解释走原生 title」契约保留正确(禁用态 title「请先连接服务商」在 Windows 真机截图可见),记录为已达标样例。
