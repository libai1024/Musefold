# UI 审计:生成历史(HistoryScreen / FilterBar / 行列表)

> 只读审议。截图:`history-list.png`。代码:`HistoryScreen.tsx`、`HistoryFilterBar.tsx`、`HistoryMaintenanceBar.tsx`。

## 总体评价

信息密度合适:状态胶囊(成功/失败)、模型等宽字、费用与耗时元信息、缩进线程(`↳`)都可读。**最突兀的是右上角「全部 / 回收站」TabsTrigger 带图标+文字**,与提示词库同款 Tabs(纯文字)语法不一;其次是筛选行的模型色块。

## 发现

### H1(中)右上「全部 / 回收站」Tabs 带图标,与提示词库 Tabs 语法不一
- 位置:`HistoryScreen.tsx:391-399`(`HistoryIcon + 全部`、`Trash2 + 回收站`,text-xs)。
- 对比:提示词库 `prompt-tab-all/trash` 是纯文字 Tabs。两屏同为「库/回收站」语义,却一套带 icon 一套不带。
- 建议:二选一统一。倾向**都去 icon**(Tabs 是位置指示,不是动作);或都带,但两屏必须一致。

### H2(中)行内模型色块(magenta 小方块)意义不明
- 截图:`history-list.png` 每行费用/耗时后一枚纯色小方块(截图中为高饱和 magenta)。这是模型色标(model color chip),但无图例、无 tooltip 时用户无法解码;且测试夹具色过于扎眼,真实模型色未必如此。
- 建议:色块加 title(模型名);饱和度压到 `color-mix 70%` 与整体灰调兼容。

### H3(中)「上游拒绝了这次生成」失败原因直接拼在元信息行
- 截图:失败行元信息为「musefold-image-pro · 上游拒绝了这次生成」,与「2 积分 · 1.5s」同级同色系,失败原因被淹没。
- 建议:失败原因单独一行 `text-destructive text-xs`,或收进行 Inspector;不要与计量信息混排。

### H4(低)「全部」Tab 与筛选「全部状态」的「全部」一词三处出现
- Tabs「全部」、状态下拉「全部状态」、日期「近 30 天」——「全部」覆盖两种语义(范围 vs 状态),新手需试错。
- 建议:Tabs 改「全部记录」或在 Tabs 下加一行当前范围说明;低成本方案是保持现状(记录语义歧义)。

### H5(低)回收站维护条(清空失败/清空已取消/清空回收站)三个同级 danger 动作
- `HistoryMaintenanceBar.tsx`:三项清理都是下拉确认项,入口合一——形态正确;但截图未覆盖该状态。按代码审议:三项描述文案都很长(30 天/失败/已取消),下拉里建议每项配数量(「移入回收站(12)」),否则用户在盲选范围。
- 建议:下拉项显示影响条数。
