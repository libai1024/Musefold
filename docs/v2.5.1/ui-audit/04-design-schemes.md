# UI 审计:设计方案(SchemesScreen / SchemeControlDeck / 导入分享包)

> 只读审议。截图:`design-schemes-list.png`、`scheme-package-preview.png`。代码:`SchemesScreen.tsx`、`SchemeControlDeck.tsx`、`SchemeTrashDialog.tsx`。

## 总体评价

列表页信息架构(草稿/正式分组、状态点、来源行)清晰。**顶部工具行是全应用文字钮最密集的地方**:「⟳ | 方案任务 | 导出记录 | 已移除 | + 新建▾」五个控件里三个纯文字,右半行拥挤;行内右侧的「试运行 / 使用」红字链也值得复议。

## 发现

### D1(高)工具行三个文字钮应收敛为 icon 或菜单
- 位置:`SchemeControlDeck.tsx:130-165`。现状:`刷新`已 icon 化(好),但「方案任务」「导出记录」「已移除」是三个 ghost 文字钮,与「+ 新建▾」挤在同一行;窄屏下最先换行/截断的就是它们。
- 建议(按用户「按钮尽量 icon 化」方向):
  - 「方案任务」→ icon `list-checks`(任务语义),title 保留文字;
  - 「导出记录」→ icon `file-down`,title「导出记录」;
  - 「已移除」→ icon `trash-2`,title「已移除的方案」。
  三者低频,收进一个「⋯」溢出菜单亦可,但 icon 化改动更小。md 以下必须收菜单(现状会换行)。

### D2(中)行内右侧「试运行 / 使用」红字动作与整行点击语义竞争
- 截图:`design-schemes-list.png`。行主体(封面+标题+来源)点击即进详情;行右缘「试运行」「使用」是裸红字(非按钮容器)。三个可点目标共享一行,hover 无视觉分区,误触即触发收费动作(试运行)。
- 建议:「试运行」「使用」改为 ghost icon 钮(与提示词行浮层操作组同语法)并入行尾浮层;或至少给胶囊底(`bg-accent rounded-full px-2`)提示可点区。

### D3(中)「+ 新建▾」下拉分裂的创建入口
- 主钮「新建」带下拉箭头(多个创建来源)。功能合理,但截图里下拉箭头紧贴文字无间距语法提示;且「新建提示词」屏的主钮无下拉——两屏「新建」心智不同。
- 建议:可保持,仅统一箭头间距(`gap-1` 已有);记录差异原因(方案有多来源,提示词只有一种)。

### D4(低)分组标题「草稿 1 / 正式 1」与行数弱关联
- 计数直接跟在标题后,无胶囊底;与提示词库标题「提示词库 1 条」语法不同。
- 建议:统一两屏的「标题 + 计数」形态(建议都用胶囊计数 Badge)。

### D5(低)导入分享包对话框三按钮文案长度接近
- 截图:`scheme-package-preview.png`「取消此上传 | 关闭 | 确认导入为草稿」。主次(default 主钮)正确;「取消此上传」与「关闭」语义接近(一个是撤上传、一个是关预览),新用户难分。
- 建议:「关闭」改「稍后处理」;或在描述里点明两者差异。

### D6(信息)状态点(橙点=进行中)无文字伴随
- 草稿行标题前橙点 + 「有取查」Badge(截图可见)承载状态;点本身无 title。建议加 `title="进行中"`。

## 汇总
