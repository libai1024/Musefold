# UI 审计:账号域(AccountPanel / 登录设备 / 云恢复 / 公告)

> 只读审议。截图:`settings-signed-in.png`、`settings-login-devices.png`、Windows 流程 `04-signed-in.png`。与 05(设置)有重叠,本文只记账号域特有项。

## 总体评价

身份行(头像首字母 + 用户名/积分 + 可生图 Badge)干净;登录设备列表字段(登录/最近使用/失效/接入 IP)完整。特有问题:**「释放所选」的动作词**、**恢复流程的输入前置**、**公告面板的刷新钮形态**。

## 发现

### A1(中)「释放所选」动词晦涩;「释放所选并登录」双语义
- 位置:`LoginSessions.tsx:405、606`。「释放」= 远端登出其他设备(行业惯用「移除/登出其他设备」);405 行还有「释放所选并登录」变体(登录冲突场景)。
- 建议:统一「登出所选设备」;冲突变体「登出其他设备并继续登录」。工具条按钮同步(见 05-T1)。

### A2(中)登录设备行复选框裸置(无 hover 语义、无全选)
- 截图:`settings-login-devices.png`。设备行首裸 checkbox;选择>0 前「释放所选」禁用。缺「全选(除当前)」快捷——逐个勾选在多设备时繁琐;checkbox 与行点击无联动(必须点中复选框本体)。
- 建议:行点击切换选择;列表头加「全选其他设备」checkbox。

### A3(中)账号恢复(AccountRecoveryPanel)输入框前置说明长
- 截图:`settings-signed-in.png`:「仅在这台设备仍登录原账号时使用。先检查恢复申请,再确认要恢复的账号。」+ 标题「另一台设备的恢复申请编号」+ 输入 + 「检查申请」。受限账号落地即见四件套,压迫感强。
- 建议:说明缩为一句放 placeholder/描述;流程改为「输入编号 → 下一步(检查)」单行。

### A4(低)公告面板「⟳ 刷新公告」按钮带 Spinner 前缀拼字
- `AccountNoticesPanel.tsx:253`:`{refreshing && <Spinner />}刷新公告`——加载中图标与文字粘连(无间距类)。同文件应有 `gap` 容器,若无则为排版缺陷。
- 建议:按钮内用 flex gap-2 包裹;或 icon-only + title(与其他「刷新」icon 化方向一致)。

### A5(低)云恢复面板(CloudRecoveryPanel)「刷新任务列表」整行文字钮
- `AccountCloudRecoveryPanel.tsx:93`:刷新是整行宽文字钮。与 A4 同方向:刷新类动作全应用应统一为 icon 钮(方案列表已 icon 化,此处滞后)。
- 建议:改 icon 钮置面板标题行尾。

### A6(信息)兑换码行(RedeemRow)输入+按钮组达标
- 截图 `settings-signed-in.png`:输入框 + 「兑换」钮组合标准;「兑换历史」入口经 `onOpenHistory`。达标样例。
