# UI 审计:移动 Web 视口(≤md 断点,跨屏横切)

> 只读审议。依据:代码断点(`max-md`/`pointer-coarse`)、移动端专用组件(抽屉/底导航)、`history-list.png` 等桌面截图的响应式推演。移动端截图基线暂缺(视觉快照仅桌面项目),标注为待补。

## 总体评价

横切纪律良好:行操作组「<md 行内常显、md+ 浮层覆盖」、抽屉导航、Composer 触屏目标(min-h-11)都成体系。审议发现集中在**移动独有组件与桌面语法的一致性**。

## 发现

### M1(中)移动头部「搜索提示词」图标钮直达提示词屏,与 ⌘K 语义分叉
- `AppShell.tsx:484`(`mobile-search`):点击 = `onNavigate('prompts')`,不聚焦搜索框;桌面 ⌘K 是「切屏+聚焦搜索」。移动用户点搜索图标后还要再点一次搜索框。
- 建议:写入 `prompts-focus-search` 意图(桌面同款),切屏后自动聚焦。

### M2(中)底导航(pb-16 预留)与侧栏导航项的集合一致性待核
- `AppShell.tsx:495`(`pb-16 md:pb-0`)为主区预留底导航高度;`app-bottom-nav` testid 存在于 E2E(见 `web.shell.spec.ts` inert 断言)。底导航项集合(应为四主屏)与侧栏一致,但「设置」只经头部齿轮进入——移动端设置入口深度 +1。
- 建议:底导航保持四主屏(正确);头部齿轮 tooltip/title 确认存在。

### M3(低)抽屉内收起钮已去 tooltip(触屏无悬停),但「展开侧栏」的 rail(md+)保留 tooltip——一致
- `AppShell.tsx` `tooltips=false` 分支已处理;记录为达标。

### M4(低)prompt 行触屏操作组六钮行内占位,行高约 +40%
- `PromptListRow.tsx`:`max-md:shrink-0` 常显六钮(含「使用」文字钮)在 390px 视口占行宽近半,标题压缩。
- 建议(与 02-P1 联动):触屏也把「使用」icon 化可省 ~56px;或触屏收进行尾「⋯」菜单(§8-I2 反对藏动作,需用户裁决——记录为两难,倾向保常显+icon 化)。

### M5(信息)移动视觉快照基线缺失
- `playwright.config.ts` 视觉基线仅桌面项目有文件;移动断点回归依赖功能断言。建议补 `workbench-empty` / `prompts-list` 移动基线各一张(不阻塞)。
