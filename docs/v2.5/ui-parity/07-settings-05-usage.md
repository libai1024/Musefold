# 07-05 设置 · 使用统计 — 旧版 vs v2.5 对照

> **旧版源码**:`UsageStatisticsSection`(256 行)+ `features/settings/UsageStatisticsCharts.tsx`(图表)+ `usage-statistics.ts`(聚合)+ `styles/usage-statistics.css`(500 行)。
> **新版**:**无对位实现**(0%)。数据侧:桌面本地渠道记录仍在 SQLite;云端 0019_cloud_sync_usage_events 迁移已建事件表——**两端数据都在积累,只是没有可视化**。

---

## 1. 结论与迁移状态

使用统计是纯消费型分区(只读、无副作用),迁移风险最低、但工作量集中在图表与聚合口径。旧版的价值主张:回答「我这个月花了多少积分、哪个渠道最稳定」。v2.5 用户当前完全无法自查用量,只能看账号卡的当前积分余额。**建议排在设置系列后段**(P2 末),因为不阻塞任何操作闭环;但**契约与聚合口径要在历史屏补成本字段(05 §7 P2)时一并定**,避免两处口径漂移。

## 2. 旧版结构存档(恢复基准)

### 2.1 汇总卡区(`settings-usage-summary`)

四张指标卡:

1. **生成成功率**——无任何尝试时显示「—」而非误导性的 0(明确注释的口径规则);
2. **账号积分消耗**(全时段,`allTimeLoaded` 才带单位);
3. **当前积分**(与账号卡同源,`formatPoints`);
4. 生成总量/渠道分布(图表区)。

分区描述:「汇总各生成渠道的用量与稳定性;**积分消耗只采用账号渠道的实际记录**」——豆包/本地渠道不计积分,这是聚合口径的关键规则,恢复时写进契约注释。页脚 `settings-usage-accounting-note` 再次说明计费口径。

### 2.2 时间范围(`settings-usage-range-*`)

分段控件 `role="radiogroup"` aria-label「统计时间范围」,预设档(7 天/30 天/全部——与历史屏筛选预设同源);切换重算聚合。

### 2.3 图表区(`UsageStatisticsCharts`)

- 用量趋势(按日折线/柱状)、渠道分布、模型分布、成功率趋势;
- 500 行专用 CSS 全部是图表配色与布局——**恢复时必须换 token 化方案**(shadcn charts / recharts + `--chart-1..5`,新 token 集已备好五个 chart 色);
- 刷新钮(`settings-usage-refresh`)手动重算;错误态 `settings-usage-error` 就地错误条。

## 4. 交互与口径规则(恢复时不可降级)

1. **无数据显示「—」**,绝不显示 0(成功率、消耗同规则)。
2. 积分消耗只统计账号渠道实际扣费记录;体验通道(豆包)与本机自备 Key 渠道显示用量但不计积分。
3. 时间范围切换是纯前端重算(数据一次拉全或按范围查询,按数据量决定;旧版按范围重查)。
4. 刷新为手动 + 进入分区自动一次;不做轮询(统计非实时)。
5. 图表空态(范围内无记录)给引导文案而非空白坐标系。

## 5. 动效与 UIUX 细节

- 旧图表有入场绘制动画(CSS/SVG stroke),reduce 下直接呈现终态——恢复时同规则。
- 指标卡数字用 tabular-nums(旧版有),避免跳动;大数 `formatPoints` 千分位。
- 范围分段控件选中滑移过渡(`--dur-fast`)。
- a11y:图表需 `aria-label` 描述 + 数据表格 fallback(旧版未做,恢复时**升级**:加 sr-only 表格,这是「做得更好」的机会点)。

## 5.1 旧版聚合口径全表(契约设计的直接输入)

从旧 `usage-statistics.ts` 与分区实现提取的口径规则,新契约逐条继承:

1. **渠道枚举**:账号(官方)/ 自备网关(byok)/ 豆包网页(体验)——新版对位:云端生成 / 桌面本地 provider;豆包随冻结面暂不进表,但枚举预留。
2. **成功率分母**:只计终态(succeeded+failed+cancelled 不含 expired?旧版为 succeeded/(succeeded+failed),取消不计入)——**恢复时以旧实现为准重读一遍再定**,契约注释写明分母定义,这是最容易口径漂移的字段。
3. **积分消耗**:仅账号渠道的 `actualPoints` 实际记录求和;预估值(预算预扣)不计;时间按扣费时刻不按提交时刻。
4. **按日序列**:自然日(本地时区)分桶;范围边界含首含尾;无记录日补 0(图表连续性),但汇总卡的「无任何尝试」判定看原始记录数而非补零序列。
5. **模型分布**:按 `providerModel` 原值分组,显示走 `displayModelName` 翻译(旧 model-catalog),未知模型显示原串。
6. **当前积分**:直接复用账号卡同一查询,不重复请求(旧版从 account store 取)。

## 5.2 状态矩阵与双端

| 状态 | 表现 |
|---|---|
| 首次进入 loading | 汇总卡数字区骨架,图表区骨架块 |
| 部分数据未到(allTime 未载) | 对应卡「—」+ 无单位(旧规则:未知不显示 0 也不显示单位) |
| 聚合失败 | `settings-usage-error` 就地错误条 + 重试;已载入的卡保持旧值不清空 |
| 范围内无记录 | 图表区引导文案「该时段没有生成记录」;汇总卡「—」 |
| ready | 四卡 + 范围控件 + 图表 |

双端:桌面从 SQLite 聚合(桥内 SQL,注意 `generation_runs` 已含成本列);云端从 `usage_events` 聚合(0019 迁移的表,api 侧 SQL);两端返回同一 `usageSummarySchema`。范围参数(7d/30d/all)进查询而非前端过滤(数据量考虑),与旧版按范围重查一致。图表库选择:优先 shadcn charts(recharts 封装),`--chart-1..5` token 已在 M3 备好;不引入新图表依赖前先确认 bundle 影响(web-next 首屏无本卡,设置路由分包即可)。
