## 1. 结论与迁移状态

新版「数据」卡是**新增的回收站聚合入口**(旧版没有,这是新版做得更好的点)。旧「数据存储」分区五大能力中,**数据库备份、存储路径、诊断日志、危险区**已随 B1-T6 迁入(桌面门控,Web 整块不渲染);**导出/导入**仍是登记暂缓域(分享/导入,CLAUDE.md),恢复时按 §2.1/§5.3 复刻。

## 2. 旧版结构存档(恢复基准)

### 2.1 导出与导入(暂缓域挂点)

- 行:「导出与导入——备份或迁移全部数据。**导出内容不含任何 API 密钥**」+ 「导出」(`open-export`)/「导入」(`open-import`)钮。
- `ExportDialog`:选择范围(提示词/历史/全部)→ 生成导出包;`ImportDialog`(343 行):选包 → 校验 → 预览统计 → 确认导入;**导入会整批改库,完成后所有视图 store 强制重读**(旧注释:「否则用户切回资源库还是旧列表」——新版对位动作是全局 query invalidation)。
- 属分享/导入暂缓域:登记勿删,恢复时 UI 按本节复刻。

### 2.2 数据库备份(`BackupPanel`,桌面 only)

- 状态行:「正在读取备份… / 暂无备份 / 共 n 份 · 最近备份 {日期}」。
- 「立即备份」:创建一致性快照(toast「当前数据库已保存为一致性快照」),**刚创建的备份直接展开可见**(省一次「查看备份」点击——已打磨的细节,保留)。
- 备份列表:逐份「恢复」(危险动作,确认后重启生效)+ 保留策略说明。
- 错误就地红字(读取失败/创建失败/恢复失败)。

### 2.3 存储位置与诊断日志(桌面 only)

- 路径行组:数据库/图片/**备份目录**(`backups`)等,每行「复制路径」(toast「路径已复制」)+「打开」(文件管理器);读取失败就地「路径读取失败:xx」。
- 诊断日志:专属行「查看/打开」,查看为内嵌文本(空=「(暂无日志)」,失败=「(读取日志失败)」)。

### 2.4 危险区(`DangerZonePanel`)

- 「清空全部数据——提示词、组合内容和生成历史将被永久清空」;**输入确认短语「清空全部数据」才可执行**(比 AlertDialog 更强的摩擦,I3 的顶格形态);成功 toast 明确边界:「Provider、API 密钥和图片文件保持不变」。

## 4. 交互与安全口径(恢复时不可降级)

1. 导出永不含密钥(旧文案是承诺,实现有测试);备份文件同规则。
2. 恢复备份必须确认 + 说明将覆盖当前数据 + 重启语义。
3. 清空数据的确认短语必须精确匹配,粘贴可用(不禁粘贴,尊重用户);成功后边界文案照搬。
4. 导入完成 = 全局 invalidation(新版机制),并 toast 汇总(导入 n 条提示词/n 条历史)。
5. 日志内容可能含路径,不含密钥(主进程日志纪律已保证);查看器只读。

## 5. 动效与 UIUX 细节

- 备份列表展开/收起:旧版直切;新建备份后自动展开的「就近反馈」细节保留。
- 危险区红色系:旧 `--danger` 边框卡;新版对位 `border-destructive/30` 卡,视觉口径一致。
- 路径行是等宽字体(旧版 mono),复制按钮 hover 渐显——与新版行动作组口径合并。
- 所有文件系统操作失败都就地报错(不只 toast),因为用户需要看着路径排障。

## 5.2 备份恢复的完整交互流(P1 任务基准)

旧流程逐步:①点某份备份的「恢复」→ ②确认对话框(标题「恢复此备份?」,正文说明「当前数据将被该备份覆盖,应用将重启」+ 备份时间)→ ③执行(全程 busy 锁整卡)→ ④主进程完成后 `relaunch`。失败在 ③ 就地红字并解锁。恢复期间不允许并行操作(创建/另一份恢复),整卡 disabled。新实现沿用;另有两条旧版没做、恢复时**做得更好**的机会点:恢复前自动先创建一份「恢复前快照」(主进程一行调用,给用户反悔路径);备份行显示文件大小(列表接口已有 size 字段则显示)。

## 5.3 导入的冲突语义存档(暂缓域,恢复时的规格)

旧 `ImportDialog` 的三段式:选文件 → 校验(格式/版本,失败就地报错不进下一步)→ 预览统计(将导入 n 条提示词/n 条历史/跳过 m 条重复)→ 确认执行 → 完成汇总。重复判定按内容指纹而非 id(跨设备迁移场景 id 必然不同);冲突策略 = 跳过(不覆盖本地),旧版无「覆盖」选项——恢复时维持跳过默认,是否加覆盖选项交给分享/导入域的产品卡决定,本篇不预设。
